📖 My SW 使用文档

欢迎使用 My SW！这是一个完全运行在浏览器本地的 AI 角色聊天应用，所有数据（聊天记录、角色、自定义内容）都保存在你的设备上，不会上传到任何服务器。本文档将带你从零开始，即使是第一次接触 AI 的真新手，也能顺利配置并开始使用。不过，使用MySW的代价是变成猫娘哦~

隐私优先

本应用不会存储你的 API Key 到任何服务器。你在「系统设置」中填写的 Key 仅保存在你当前浏览器的本地存储（localStorage）中，清除浏览器数据会一并清除。

🚀 快速开始（5 分钟）

如果你是急性子，只想立刻开始聊天，按下面三步走即可：

  1. 注册一个 API 平台账号并充值 推荐从 OpenRouter、硅基流动、DeepSeek 官方 等平台开始，注册简单、支持支付宝/微信。
  2. 在 API 平台创建一个 Key 进入「API Keys」页面，点击「Create new key」，复制以 sk- 开头的那串字符。
  3. 回到本应用，依次填入 API 地址、Key、模型 点右下角齿轮 ⚙️ →「AI 配置」标签 → 填好三项 → 点「保存设置」。

🎯 新手怎么用：先跑通，再玩花

这个站功能很多，但真正用起来只需要顺着一条线走。下面按「越往后越花」排，卡住了再往下看对应的章节。

第 0 步：让一条消息能发出去

  1. 配好 API 地址 / Key / 模型（下面 初次配置 有手把手），点「测试连接」看到绿灯就行。
  2. 随便挑一个内置角色，发一句「你好」，能看到回复 = 地基打好了。
  3. 这时候再动别的设置。功能是叠加上去的，地基不通，后面看到的所有报错都只是同一个问题。

第 1 步：把角色捏成你想要的样子

  • 内置角色改人设：点「添加好友」→ 角色行右边那个铅笔 ，直接改提示词。有多个提示词版本的角色可以一个版本一个版本地改，改过的会挂「已修改」标签，点「恢复初始版本」就回到原文（标签会变淡，记着你曾经动过）。
  • 自制角色：同一个入口 「创建新角色」，写名字 + 提示词 + 开场白。写好之后也能在铅笔里 新增提示词版本（比如一个「日常版」一个「剧情版」），随时切换。
  • 提示词写不好：把「身份 / 外貌 / 性格 / 说话方式 / 关系 / 禁止事项」分成小标题写，比一整段散文有效得多。写完了可以点提示词下面的「优化」让它自己找一遍前后矛盾。

第 2 步：让它「记得住」—— 三件套的搭配

角色忘事，通常是这三件事没配对，而不是模型笨：

你在意什么该开什么怎么调
记得住几十轮前的剧情上下文轮数 + 对话摘要轮数拉到 20~40；开摘要，让早期内容压成一段带进上下文。
记得住设定（地名、组织、人物关系）世界书把设定写成条目 + 关键词，只在聊到时才注入，比塞进提示词省钱。
跨对话记得住你这个人长期记忆开「自动提取」，它会定期把重要信息写进记忆档案；嫌吵就把提取频率调高。
角色主动来找你主动关怀配合「感知现实时间」一起开，它才知道现在是凌晨三点还是下午茶。

第 3 步：让它「像在演」—— 最划算的几个开关

  • 消息分段 + 气泡最大宽度：分段让长回复按段落分成几条气泡，读起来像真的在聊天；宽度调到 60~70% 最像手机。
  • 视觉小说模式：立绘 + 背景 + 打字机 + 情绪识别。想让角色「站在那里说话」，这是性价比最高的一档。配好角色立绘后，/vn 一键进入。
  • 立绘情绪：给角色传几张不同表情的立绘，AI 会按回复内容自动切表情，不需要你在提示词里写「现在该笑了」。
  • 变量与状态栏：想让角色有「好感 / 体力 / 金币」这种会变的状态，用变量模块，AI 回复里带状态更新，界面会实时显示。

第 4 步：省点钱

  • 上下文不是越长越好：每轮都要把历史重发一遍，轮数翻倍 ≈ 费用翻倍。先调小，觉得忘事再往上加。
  • 缓存：站点支持缓存（DeepSeek / OpenAI / Claude / Kimi）时，把固定不变的部分（人设、世界书）放在前面，命中率会高很多。
  • 专用模型：给「摘要 / 记忆提取 / 翻译 / 主动关怀」单独指定一个便宜模型，主对话继续用好模型。这一项通常能砍掉三到五成费用。
  • Code 模式：让 AI 写代码时打开，会把输出上限抬高、关掉分段（分段会把代码撕成好几条）。

⚙️ 初次配置步骤（手把手）

第一次打开应用时，由于没有配置 AI 接口，发送消息会提示 ❌ 请先在设置中配置 API 地址和 Key！。这是正常现象，请按下面的步骤配置：

第 1 步：打开「系统设置」

在聊天界面左下角（或移动端右上角）找到 齿轮按钮，点击它。会弹出一个标题为「系统设置」的模态框。模态框顶部有多个标签页：AI 配置 / 界面外观 / 聊天设置 / 导入导出 / 知识库 / 长期记忆 / 世界书 / 快捷键 / 插件 / 实验室 / 更多 / 插件 / 实验室。第一次使用我们只需要关注 「AI 配置」 即可。

找设置项更快

设置弹窗顶部有一个 搜索框，输入关键词（如「Key」「温度」「气泡」）可以快速跳转到对应设置项。

第 2 步：填写「API 调用地址」

这是你的 AI 服务提供商的接口根地址。本应用支持三种接口协议：OpenAI 兼容、Claude（Anthropic Messages）、Gemini（Google generateContent）。填到域名部分即可，路径由系统按协议自动补全。

下方的「接口协议」一般留「自动识别」就行：地址里出现 /v1/messages 判为 Claude，出现 :generateContent 或 /v1beta/models/ 判为 Gemini，其余一律按 OpenAI 兼容处理。只有当中转站路径不规范、自动判断不准时，才需要手动锁定。

关于浏览器直连

这三种协议都是纯前端直连，不需要自建后端。但有两点要清楚：

  • Anthropic 官方对部分地区返回 403 Request not allowed，这不是配置错误，和地址填错无关。国内请使用支持 Claude 的中转站，或走海外网络。
  • Gemini 可以直接填 Google 官方地址，也可以把中转站给的带 {model} 占位符的地址整条贴进来 —— 占位符会自动替换成模型名，流式地址也会自动切换。如果中转站给的是 OpenAI 兼容路径（/v1beta/openai/chat/completions），选「OpenAI 兼容」更省事。
  • API Key 存在你自己的浏览器里，请求直接从你的浏览器发往服务方，不经过本站任何服务器（本站也没有服务器）。反过来说，同一台设备上能打开这个页面的人，也能在开发者工具里看到 Key。

📌 进阶：生成参数调节

在「AI 配置」页面下方还有几个可选参数，新手可以先保持默认：

  • 随机性 (temperature)：0~2 之间。值越大 AI 回复越有创造性、越发散；值越小越稳定、越像标准答案。角色扮演建议 0.8~1.2。
  • 核采样 (topP)：0~1 之间。默认 0.9。和 temperature 二选一调即可，不要同时大改。
  • 思考强度 (reasoning_effort)：默认「不设置」，由模型自己决定；越高想得越久、答案越稳，也更慢更贵，「关闭」则直接回答。不同接口字段名不同：OpenAI 兼容 reasoning_effort、Claude thinking.budget_tokens、Gemini thinkingConfig.thinkingBudget，不支持的接口会忽略。选了具体强度后可填「思考预算 tokens」，留空按档位折算（极低 1k / 低 2k / 中 8k / 高 24k）。
  • 最大上下文 (maxContext)：AI 能「记住」的历史消息轮数。太小会失忆，太大会更贵。
  • 单条回复上限 (maxTokens)：限制 AI 单次回复的长度，避免无限生成。

🔑 什么是 API Key？

你可以把 API Key 理解为一把「钥匙」或「通行证」：

当你在本应用里向 AI 提问时，应用会把你的问题通过 HTTPS 加密发送到 AI 服务商（OpenAI、DeepSeek 等）的服务器。服务商怎么知道这次请求是你发出的、应该由谁付费呢？答案就是——靠 API Key。

把它想象成酒店房卡：

  • 🔒 私密：谁拿到你的 Key，谁就能冒充你调用 AI，产生的费用全部算到你账上。
  • 💳 付费凭证：AI 平台根据你的 Key 记录调用量并从你预充值/绑定的账户里扣款。
  • 🪪 可重置：每个平台都允许你随时「作废」旧 Key、生成新 Key（一般在「API Keys」页面）。

  • 📌 适合：知道每次聊多久、价格敏感、需求短平快的用户。

📊 快速理解「Token」

看完上面你可能还是有点抽象，这里用三个比喻帮你彻底搞懂：

  1. 📞 Token 就像手机话费的「分钟数」：通话时间越长，扣费越多。Token 就是 AI 的「通话时间」。
  2. 🛒 Token 就像超市的「斤两」：1 斤米 3 块钱，1 斤面 4 块钱。AI 模型是「商品」，Token 是「重量」。
  3. 📖 Token 就像书本的「字数」：一本 10 万字的小说 = 约 15 万 Token。

所以：

  • 💬 简单聊天 1 小时 ≈ 几千到几万个 Token ≈ 几分到几毛钱
  • 📚 让 AI 写一篇 3000 字文章 ≈ 5000~8000 Token（仅输出）
  • 🎬 长篇角色扮演 RP 一晚上 ≈ 几十万 Token ≈ 几毛到几块钱
省钱小技巧
  • 在设置中把 最大上下文轮数 调小（如 5~10 轮），可显著减少输入消耗。
  • 不需要 AI 思考/长篇大论时，用 deepseek-flash 这类便宜模型即可。
  • 把大段写作放到 DeepSeek 的空闲时段：高峰只有工作日 09:00–12:00、14:00–18:00（北京时间），其余时间——午休、晚上 18 点后、凌晨、以及周末和法定节假日全天——都算空闲，价格是高峰的一半。
  • 人设和世界书放在提示词最前面、内容别乱改，能吃到缓存命中价——DeepSeek 命中价只有未命中的五十分之一。

🎭 创建与编辑角色

本应用的核心玩法就是自定义角色。每个「角色」本质上是一段 系统提示词（System Prompt），告诉 AI「你是谁、应该怎么说话、有什么背景」等。

改内置 / 预置角色的提示词

「添加好友」列表里每个角色右边都有一支 铅笔，点开就能看和改它的提示词 —— 内置角色、市场里的预置角色都行，不用先复制成自定义角色。

  • 按版本分别改：有多个提示词版本的角色，下拉里一个版本一份内容，改哪个只影响哪个。
  • 已修改 / 已还原：改过之后角色名旁边会挂一个「已修改」；点「恢复初始版本」就完全回到原文，标签会变淡成「已还原」（表示你动过，但现在和原版一致）。嫌碍眼可以在弹窗里勾「不再显示这个标签」，第一次要同意一条声明：别拿篡改后的人设去造谣本站。
  • 存在哪：改动只写在这台设备的浏览器里，不上传、不覆盖官方原文；导出角色卡时带的是你改后的内容。
  • 自定义角色也能建版本：自己的角色、导入的角色，弹窗里有「+ 新增版本」，复制当前内容出一个新版本，可以一份写日常、一份写剧情，随时切。

方式一：点击 ➕ 添加角色

左下角点击 「添加好友」 按钮，会弹出角色编辑窗口。填写以下字段：

name *
角色名，例如「银狼」「流萤」。会显示在聊天列表和消息气泡上。
avatar
角色头像。建议填图片 URL（支持 jpg/png/webp/gif），或使用图床链接。空着会用默认头像。
persona / 人设
核心字段。详细描述角色的身份、性格、说话方式、背景故事。写得越具体，AI 越像这个人。
greeting / 开场白
用户进入聊天时 AI 自动发送的第一句话。可以是问候、自我介绍或场景描写。

标签（可选），便于搜索。例如「崩坏：星穹铁道 / 黑客 / 毒舌」。
systemPrompt
高级字段，会以「系统级」指令注入到对话最前面。优先级高于人设。

写人设的实用技巧

一个高质量的人设通常包含这几部分：

  1. 基本信息：年龄、性别、外貌、职业。
  2. 性格特征：用具体词汇描述，如「毒舌但关心人」「外冷内热」。
  3. 说话风格：举 2~3 个示例句（非常有效！）。
  4. 背景故事：来龙去脉、动机、关系网。
  5. 行为边界：明确不希望 AI 做什么（如「不要主动结束对话」「不要重复我的话」）。

示例：极简但有效的人设

你是「银狼」，19 岁天才黑客少女，崩坏：星穹铁道角色。
性格：毒舌、慵懒、惜字如金，但内心重情义。
口头禅：「啧，太简单了」「一群菜鸟」。
说话风格：短句、夹带电子游戏术语和表情包。
示例：
- 用户：「在吗？」 → 银狼：「有事说事，别浪费我挂游戏的时间。」
- 用户：「我今天心情不好」 → 银狼：「……要黑客进你的仇人系统吗？免费的。」
请永远以银狼的第一人称视角回复，不要用敬语。

开关关掉之后
消息滑动（多版本回复）「重新回答」回到覆盖旧回复的老行为，气泡下方的 ‹ 2/3 › 不再出现。已有的多版本记录不会删，重新勾上还能切。

变量与状态栏状态栏与顶栏入口隐藏，{{getvar}} 等宏原样保留，AI 回复里的变量指令当普通文字显示（不再执行、也不再从正文里摘掉）。想连脚本都不下载，去「加载 JS 文件设置」关掉「变量与状态栏」。
群聊自动模式（总开关）所有群聊立即回到「按活跃度随机挑人」，正在跑的自动接话会被中断。每个群自己的「自动模式」勾选仍然保留，总开关重新打开就继续按各群设置走。

原则是只关「要不要用」，不动数据：多版本记录、变量数值、世界书里的概率/定时字段、备用开场白都不会因为关开关而丢失。面板底部会实时显示「当前已关闭：…」，方便确认状态。

世界书的高级触发：递归 / 概率 / 定时

世界书条目除了「🔵蓝灯常驻」「🟢绿灯关键词」之外，还支持酒馆那套高级规则（在条目编辑框的「高级触发」里改）：

能力怎么用
递归扫描已触发条目的内容也会进入扫描范围，其中出现的关键词能继续触发别的条目，像多米诺一样连下去。层数在书顶部「递归层数」里调（最多 5 层）；单条可以关掉「允许被其它条目递归触发」，它就不会被别人的内容带出来。
概率触发勾「按概率触发」并填百分比：关键词命中后再掷一次骰子，只有 X% 会真的注入。适合「偶尔才想起来」的细节。
定时生效（持续）填「持续 N 轮」：命中后接下来的 N 轮即使不再提关键词也继续生效，用来做「这段时间一直在下雨」这类持续状态。
冷却生效结束后的 N 轮内不再触发，避免同一段设定每隔一句就重复注入。
延迟对话进行到第 N 轮之后才允许触发，适合晚些才登场的伏笔。

这些字段与酒馆的 sticky / cooldown / delay / probability / excludeRecursion 一一对应，导入导出都会保留（递归语义相反：酒馆叫「排除递归」，这边是「允许递归」）。计数按「这个会话的第几轮对话」走，存在本机。

上下文 Token 预估与「冻结」

输入框上方常驻一行「上下文 ≈ N tokens」：按「人设 + 最近若干条消息（或聊天设置里的上下文轮数上限）+ 输入框草稿」估算，中文约 1.6 字/token、西文约 4 字符/token，是估值不是 API 的真实 usage。

点旁边的「冻结管理」可以把任意几条消息勾成不发给模型：聊天记录不删、界面照常显示，只是不再进入上下文，随时能解冻。长对话想省 token、或想把某段跑偏的剧情从上下文里摘掉时很有用；冻结名单跟着这条对话一起保存，也会跟着备份走。

消息滑动：同一条回复保留多个版本

对 AI 的回复不满意时，点气泡下方的刷新按钮「重新回答」，新的一条不会覆盖旧的，而是作为同一条消息的新版本接在后面，气泡下方出现 ‹ 2/3 › 这样的版本号，用左右箭头来回切，挑一版满意的留着。最多保留 12 版。

  • 切换版本会改变这条消息的实际内容（上下文、导出、重新生成都按当前版本走），聊天记录不会因此变长。
  • 版本跟着这条对话一起保存：切换角色、切到别的对话、刷新页面都会保留，回来还能继续切。
  • 对不在末尾的消息点「重新回答」，旧的实现会把它之后的对话一并删掉再生成——现在会先弹确认告诉你要删几条，避免误以为「版本被吃了」。
  • 只在单聊的最后一条 AI 文本消息上生效；群聊里一条回复可能被拆成多条成员消息，硬合并会把它们搅乱，所以群聊仍是原来的「删掉重来」。
  • 开了「消息分段」时，重新回答会强制按一条消息生成，并把上一次那一批分段整批替换（第 1 版是拼回来的全文），不会出现「换了最后一段、前面几段还留着」。

这个角色（默认）跟着角色走，换对话不变；适合「HP 掉到 0 就重开一段剧情」这类。
这条对话只属于当前这条对话；想给某段支线单独一套数值时，在这里写同名变量即可覆盖。

让 AI 维护数值：AI 可以直接在回复里写 {{setvar::金币::320}}、{{addvar::HP::-12}}、[var: HP-5]、[var: 金币=300]。这些指令会被系统执行并从气泡里摘掉（用户只看到干净的正文），状态栏数值实时变化，还会在旁边闪一下「HP -12」的变化量。开关打开时每次请求还会把当前变量值告诉模型，否则它不知道 HP 还剩多少。

群聊的「自动模式」

双击群名打开「管理群聊 → 群聊节奏」，勾上自动模式（让 AI 决定下一个说话人），群聊就从「按活跃度随机挑一批人同时回」变成串行接力：A 说完 → 让模型看一眼最近的对话判断「接下来该谁说，或者该停了」→ B 接着说 → ……

  • 一定会有上限：「自动最多连说」默认 4 轮（1~12）。没有上限的话两个 AI 很容易互相客套到几百条。
  • 模型输出 STOP、或某个成员表示「不回应」时，自动链立即结束。
  • 接话期间输入框上方有个「自动接话中… 点此停止」的浮动按钮；发新消息、切到别的对话也会打断。
  • 每次接力会多发一次很小的调度请求（只让模型回一个名字或 STOP），比随机挑更连贯，但更费 token。原来的「单轮最多发言 / 被cue后接话率」在自动模式下不生效。

多开场白

从酒馆导入的角色卡常带好几条 alternate_greetings。现在开新对话时会从「主开场白 + 所有备用开场白」里随机挑一条显示；不满意可以点气泡下方的「↻ 换个开场白」重掷（每条对话自己记住抽到哪条，不会每次进聊天都变）。

粘贴文本导入对话

从别的网站复制下来的聊天记录、截图 OCR 出来的文字、纯文本导出的对话，都可以直接粘进来变成本站的一条对话。入口有两个：聊天页顶栏的 文本 图标，或「设置 → 导入导出 → 粘贴文本导入」。

  • 认得常见写法：我：… / 角色名：… / 【名字】… / **我**：… / User: … / Assistant: …。名字对不上号也没关系，两个陌生名字会按出现顺序自动分到「我 / 角色」两侧；整段没有标注时会当成 AI 的一段话。
  • 可以让 AI 拆：格式很乱（带时间戳、带「复制」按钮文字、一大坨没换行）时勾上「用 AI 智能解析」，会把文本切块交给模型整理成对话；模型只做切分和标注，不改写内容。解析失败会自动退回本地规则，不会卡住。
  • 先看再导：点「先解析看看」会给出「识别到 N 条（我 X / 角色 Y）」和前 40 条预览，确认没问题再点「导入」。改了正文没重新解析的话，点导入会自动按新内容重来一遍。
  • 导到哪里：默认追加到当前对话末尾，也可以选「新建一条对话」。导入的是当前打开的角色，不会新建角色；群聊暂不支持（一条消息分不清是哪个成员说的）。

从 DeepSeek 导出包导入

DeepSeek 网页版「设置 → 数据管理 → 导出数据」会给一个 zip（里面有 user.json 和 conversations.json）。在「设置 → 导入导出」里选它，或直接选里面的 conversations.json，就能把整段历史搬过来。

  • 每段对话 → 一条对话记录：会先列出包里所有对话（标题、时间、条数），勾选要导入哪几段；同名的自动加「(2)」。
  • 谁说的：DeepSeek 的提问记成「我」，回答记成角色。可以选导入到当前打开的角色，或新建一个「DeepSeek」角色专门装这些记录。
  • 思考过程可保留：DeepSeek 的「已深度思考」内容会存成消息的思考块，显示在回复上方（可折叠），不需要的话取消勾选即可。
  • 分支只导主线：在 DeepSeek 里重新生成会岔出多条分支，这里取最长的那条路径导入；清单里会标注「含 N 处分支」，避免同一段对话被展开成好几条。
  • 不读账号信息：user.json 里的邮箱等一律不读取、不保存。

转换规则说明：世界书的「蓝灯 / 绿灯 / 黄灯」对应酒馆的 constant / 普通 / selective+keysecondary，注入位置对应 position 0 与 1，条目深度对应 depth；酒馆的触发概率、冷却、分组、递归上限这些站内没有的字段不迁移（导入时按「不改变行为」的默认值处理）。预设按「注入位置」对齐：普通提示进主提示词，注入到对话里的（如 jailbreak）进历史后指令，采样参数不迁移（站内温度等在「AI 配置」统一管理）。

🛍️ 角色卡市场

「角色卡市场」（character.html，侧边栏顶部的市场按钮）是一个独立页面，用来集中管理角色卡。它与主站共用同一批本机数据，在市场里改完，回到短信页刷新即可看到。

三个标签页

  • 我的角色：列出已加进主站的角色（内置 + 自制 + 从市场添加的）。可以搜索、按分组筛选、按最近聊过 / 名称 / 分组 / 添加顺序排序。
  • 角色卡市场：货架。预置角色卡和站内内置角色都在这里，点「添加到主站」才会真正加进来。
  • 分组管理：新建、重命名、删除分组（删分组时组内角色会回到「默认」，角色和聊天记录都不受影响）。

批量操作

点卡片右上角勾选框（或顶部「全选」）选中多个角色，底部会出现批量操作栏：移动到分组 / 新建分组并移入 / 开启群聊 / 移出主站 / 彻底删除。移出与彻底删除的区别：

  • 移出主站：角色从列表消失，但角色卡数据和聊天记录都保留，之后可以再添加回来。
  • 彻底删除：角色设定与它的全部聊天记录都会被清空，不可恢复。

角色提示词是按需加载的

这是角色卡市场存在的前提：打开网站时不会加载任何角色的提示词。

  • 内置角色的设定拆成了单独的文件（character-packs/*.js），打开网站时只加载角色索引（名字 / 头像）；
  • 只有当你点进某个角色的聊天，才会去取它那一份设定；
  • 在角色卡市场里，卡片正文也只有点「查看设定」或「添加到主站」时才会下载。

所以在市场里看到一张卡，并不等于它的设定已经进了你的上下文——你不感兴趣的角色，它的提示词根本不会进入你的浏览器。

想投稿自己的角色卡？

角色卡市场目前不提供站内上传：想把自己的角色卡投稿到市场，请通过 QQ 群或邮箱把角色卡文件（JSON / 角色卡导出文件）发给维护者，审核通过后就会上架到预置角色卡里。插件投稿同样走这两个渠道，见「插件编写指南」。

🧵 对话线程：一个角色可以有很多条对话

同一个角色下的每一条对话都是一份独立的存档：剧情、上下文、变量、世界书绑定各算各的，互不干扰。想「重开一条线看另一种发展」时用它，不用另建角色。

新建与切换

  • 新建：聊天头部的多对话按钮（或斜杠指令 /new）新建一条空对话，角色会按开场白重新打招呼。
  • 切换：同一处下拉里按需切过去；侧栏对话列表也会显示每个角色的对话数量。
  • 改名 / 删除：/rename 新名字、/del，或者在那个下拉菜单里操作。

查看全部对话：/ls（现在可以直接点）

在输入框里发 /ls，聊天区会弹出一份当前角色的对话列表：每条带编号、名字、最后一句预览和消息数，点任意一行就直接跳到那条对话，不用再记编号或者切菜单。

  • 当前标签：标出你现在正在看的那条。
  • 分页：超过 50 条时列表分页，底部会提示 /ls 2 看下一页。
  • 快捷键：列表是普通链接，键盘 Tab 选中、Enter 跳转。
列表不占上下文

这份列表只是显示在聊天区的一段临时内容，不会写进聊天记录，也不会发给 AI —— 切换对话或者刷新之后就没了。

🎭 语C：我来演一个角色

默认情况下，AI 把「你」当成你自己。语C 模式把这件事反过来一点：你挑一个角色来演，AI 仍然只演它自己，两个人对戏。开关默认关闭，位置在「设置 → 聊天设置 → 语C（对戏）」。

怎么开

  1. 打开开关勾上「语C模式（我来演一个角色）」，下面会展开两个字段。
  2. 选你演的角色下拉列表就是你的角色列表（群聊不出现）。选中谁，你就演谁。
  3. 要不要加额外设定可选。比如「他刚输了棋，心情不太好」「她还不知道你就是那个叛徒」。留空就完全按角色卡原本的设定来。
  4. 保存设置点设置面板右下角的「保存设置」开始生效；之后每一条发给 AI 的消息都会带上这段说明。

开了之后会怎样

  • AI 会把你说的每句话都当成那个角色说的，用它自己的性格和口吻回应，可以直呼其名。
  • 它不会替你（那个角色）发言，也不会描写你的动作和心理——戏是你在写。
  • 角色卡本身一个字都不改：语C 只影响发给 AI 的提示词，不改你选的那个角色的设定，也不写进聊天记录。
  • 只对单聊生效；群聊里不注入。

为什么没有「自定义语C角色」

因为已经有了：「设置 → 世界书 → 用户人设（Persona）」。那里本来就能写「你在这个故事里是谁」——名字、身份、性格、背景，会作为用户侧设定注入上下文。

两者只是两种填法，效果都是「你以某个身份说话」：

  • 语C：直接套用角色列表里某个角色的完整人设（几千字的角色卡照搬），适合「我想演已有角色」。
  • 用户人设：自己写一段自由描述，适合「我想演一个原创角色 / 我自己」。可以同时存在，语C 的说明排在后面、优先级更高。

所以这里不再单独做一套「自定义语C角色」的编辑器 —— 那是把「用户人设」重写一遍，两边还会打架。

AI 把你当成「双重人格」怎么办

这是最常见的症状：你在演「花火」，但昵称还是上一场用的「三月七」，AI 就会在回复里纠结「你到底是谁」，甚至自问自答。

原因很简单：默认会把你账号昵称单独告诉 AI（当前与我对话的用户名字是：三月七），语C 又告诉它「用户在演花火」，两条信息在它眼里是两个人。

  • 最省事：到「设置 → 聊天设置 → 上下文与记忆」里关掉 「把『我的昵称』发给 AI」。关掉后它完全不知道昵称，只能用「你」。
  • 或者保持开启 —— 语C 会自己补一句「昵称只是账号名，不是第二个人，称呼统一用角色名」，把这两条缝起来。
  • 或者把昵称改得和你要演的角色一致，两条信息自然就不打架了。
两个容易踩的点

别选成当前正在聊的那位。你和 AI 演同一个角色，两套人设会互相顶，这种情况插件会直接跳过注入，等于没开。

效果看模型。语C 给的是一段说明文字，模型照不照做取决于它本身；上下文越短、角色卡写得越清楚，入戏越稳。

📚 世界书（Lorebook）

「世界书」位于 设置 → 世界书 标签页，功能类似「酒馆（SillyTavern）」的世界书 / Lorebook：它是一份背景知识集合，AI 聊天时会根据对话内容动态挑选相关条目注入提示词，让 AI 了解世界观、地名、人物关系等设定，而不必把所有设定一股脑塞进角色提示词。

核心概念

世界书（WorldBook）

条目的集合，有名称、生效范围、启用开关和默认扫描深度。

条目（Entry）

最小单位：一段独立的背景知识 + 触发条件。例如「圣塔玛卡王国的历史」「主角的剑术流派」。

关键词（Key）

触发条目的「暗号」。当关键词出现在最近几条消息中时，对应条目会被激活。

扫描深度（Scan Depth）

在最近多少条消息中查找关键词，全书有默认值，每个条目也可单独覆盖（0 = 使用全书默认）。

两种激活策略（灯色）

  • 🔵 蓝灯（Constant，常驻）：无论聊什么，条目内容始终注入提示词。适合核心世界观、重要人物关系等必须让 AI 时刻知道的设定。蓝灯条目可以不填关键词。
  • 🟢 绿灯（Normal，关键词触发）：只有当关键词出现在最近 N 条消息中时才注入。适合不会每轮都用到的细节设定，按需激活可以显著节省 token。
插入位置

每个条目还可以选择插入位置：人设前（before）或人设后（after）——即世界书内容放在角色 System Prompt 之前还是之后。核心规则建议放人设前，补充细节放人设后。

四种生效范围（Scope）

范围说明
🌐 全局对所有角色和聊天生效，适合通用世界观。
👤 角色绑定到某个角色，只在与该角色聊天时生效。
💬 聊天绑定到某个具体会话线程，只在该线程中生效。
🎭 人设绑定到你创建的某个用户人设，当你在「用户人设」中切换到该人设时生效。

创建与编辑

  1. 创建世界书在「设置 → 世界书」中点击「创建世界书」，填写名称并选择生效范围与绑定目标。
  2. 进入编辑界面点击世界书卡片上的「编辑条目」，会打开一个独立的全屏弹窗编辑器（与编辑角色的弹窗风格一致），在这里管理全部条目。
  3. 添加条目点击「添加条目」，为每个条目填写：关键词（逗号分隔）、条目内容、激活策略（蓝灯/绿灯）、插入位置、扫描深度。所有修改即时自动保存，无需手动点保存。
  4. 完成编辑点击「完成并关闭」或右上角 ✕ 返回列表，所有修改已生效。

导入 / 导出

  • 导入 txt / md：按空行或 Markdown 标题自动切分为条目；首行若是 关键词：xxx 或 【xxx】 会自动解析为关键词，有关键词的条目设为绿灯，没有的设为蓝灯。
  • 导入 JSON：直接兼容酒馆（SillyTavern）世界书 JSON，关键词、灯色、插入位置、扫描深度、启用状态都会自动转换。
  • 导出：每本世界书可单独导出为 JSON 文件备份或分享。

用户人设（Persona）

世界书标签页底部可以管理用户人设：

  • 多个人设：可以创建多份不同身份的人设（如「冒险者·夜羽」「星际商人·老周」），用顶部的下拉框随时切换当前使用的人设。
  • 注入对话：当前人设的描述会作为上下文注入对话，让 AI 知道「你是谁」。
  • 重命名自动迁移：修改当前人设的名称再保存，会自动迁移描述，并且绑定到旧人设名的世界书也会跟着更新绑定。
  • 绑定世界书：生效类型选「🎭 人设」的世界书，会在你切换到对应人设时生效。

🎬 视觉小说模式（Galgame）

把聊天界面变成 Galgame：沉浸式背景 + 角色立绘，对话以底部对话框逐句呈现，并按 AI 回复的情绪自动切换对应立绘。舞台只覆盖消息区，底部输入框照常可用，随时可以返回普通聊天。想要更纯粹的体验可以打开全屏舞台（见下文），让画面铺满整个屏幕。

进入与退出

  • 三个入口：聊天头部右上角的 按钮、「设置 → 界面外观 → 视觉小说模式」里的进入按钮（面板中还会实时显示当前角色配了几张立绘），或在输入框里输入 /vn（/vn on 进入、/vn off 退出）。/立绘 则直接打开立绘与背景设置。
  • 退出：点舞台右上角「退出 VN」，或按 Esc。退出后自动把普通聊天滚到最新一句。
  • 模式状态会被记住，刷新页面后仍保持上次的模式；退出后马上再进来会停在你刚读的那一句并整句落定，不会把那句话重新打一遍。
  • 分段回复不再被重放：开了「分段显示」时长回复会拆成多条气泡，回复刚落库时舞台会自动跟进到这批分段的第一段（而不是末段），并且这一段会从第一页开始整段落定 —— 你在流式阶段已经读完的内容不会被打字机重新敲一遍，接着往后读即可。
  • 回复正在生成时切进舞台，会立刻接上已经出现的文字继续看，不用等这条回复说完。

立绘与背景素材

  • 按「角色 × 情绪」绑定，共 12 种情绪（default / happy / sad / angry / shy / surprised / neutral / love / excited / thinking / laugh / cry）。未设置的自动回退 default，再回退角色头像。
  • 每张立绘都支持本地上传与图片直链两种方式；本地大图会自动压缩（立绘 1000px、背景 1600px），超出 localStorage 的部分存入 IndexedDB。
  • 背景可按角色单独设置，也可设置全局背景兜底；还可以给某个情绪单独配一张背景（如「生气」时切到雷雨场景），情绪切换时背景会交叉淡入。
  • 批量导入：一次选择多张图片，按文件名自动匹配情绪（happy.png、立绘-开心.jpg；bg-happy.png / 背景-开心.jpg 为该情绪背景）。
  • 跨设备迁移请用弹窗底部的「导出 / 导入配置」（JSON）。

情绪识别优先级

逐句手动覆盖（点对话框上的情绪徽标）> [emo:xxx] 显式标签 > 关键词打分 > 默认。在外观面板勾选「要求 AI 标注情绪」后，会在系统提示中要求 AI 每次回复先给出 [emo:happy] 一行，立绘切换最准确（会改变提示词）。

其它渲染细节：长句会自动分页（一屏读不完时按句切页，点击 / 滚轮 / 按 → 翻页）；背景支持缓慢推移（Ken Burns）、压暗与虚化；情绪还会给背景叠一层极淡的氛围光染色，无需额外素材。

舞台上的对话不会出现 [emo:happy] 这类内部控制标记：即便你没开「显示回复里的思考段落」，普通聊天气泡里也会一并剥离。等待 AI 开口时，对话框上会显示「正在组织语言」的跳动小点；说话人名字旁带一枚小头像，群聊里每个角色还会各自主配色（含群头衔），方便分辨谁在说话。

全屏舞台（界面铺满整个屏幕）

舞台工具条上的 按钮、按 F、或在「设置 → 界面外观 → 视觉小说模式」里勾选「全屏舞台」，都能让 Galgame 界面占满整个屏幕：聊天头部、免责声明、左侧角色栏全部收起，并同步进入浏览器原生全屏（隐藏标签栏与地址栏）。

  • 输入框仍然可用：输入区被搬成一枚悬浮在对话框上方的浮条，打字、发图、语音、表情、快捷指令全部照旧，功能与快捷键没有任何削减。
  • 立绘与对话框自动让位：抬升量按悬浮条的实测高度计算（CSS 变量 --vn-fs-lift），输入框撑高到多行也不会盖住台词。
  • 长句分页会重新计算：舞台变高后一屏能放下的行数变了，会自动重新分页并停在原句，不会把已读的内容重打一遍。
  • 退出方式：再按一次 F、点同一个按钮、或按 Esc。注意浏览器会先吃掉第一次 Esc 用来退出原生全屏（舞台随之退回窗口内），再按一次 Esc 才返回普通聊天。直接用 F11 / 浏览器菜单退出原生全屏时，舞台样式与偏好会同步跟随，不会残留隐藏状态。
  • 状态会被记住：偏好随 VN 设置一起保存，下次进入视觉小说模式仍是全屏。「移动视图」下全屏只占满那个 430×844 的手机外框，不会把手机预览撑成浏览器窗口。

📝 GAL 工作室：自己做一个视觉小说

上一节的视觉小说模式是「和 AI 一起演」，GAL 工作室是「自己写、自己导」。它是一个独立的网页工具，用节点把剧本拼起来，做完一键导出成单个 HTML 文件 —— 不联网、不需要服务器、不用装任何东西，双击就能玩，也能直接发给别人。

剧本转 GAL：把本子丢进去，出来的东西能点

右上角有个「剧本转 GAL」。它不替你写故事 —— 故事是你写的。它只做一件体力活：把你写好的小说片段、大纲、对话本子拆成一组节点，谁在说话、什么时候换场景、哪里该给选项、哪句该做成分支。生成完先给你看统计和开头几行，确认了才写进作品；不满意可以「再写一版」，也可以「接到当前作品末尾」接着往下排。

选项作用
节点数短篇 25~40 节点 / 中篇 45~70 / 长篇 90~140。节点越多，一次拆下来越慢，也越容易把你的本子拆散。建议先按中篇来。

怎么让它写得像人

它擅长「拆」，不擅长「想」。你给的东西越具体，它拆得越好：谁、在哪、想要什么、哪句话没说出口。只写「一个悲伤的故事」，它会还你一堆正确的废话。

生成完先看开头六行。第一句不对，后面全歪 —— 直接「再写一版」，比逐条改快。

它只写文字层：台词、旁白、出场、退场、选项、跳转、结局。图片和音乐只能从素材库里拿现成的，它不会画图，也不会编造一个不存在的文件名。跳转目标对不上、素材被删了，这些它自己会处理并在结果里列出来。

三种常见失败

请求发不出去：多半是接口不允许网页直连（CORS），或者地址填错了。本地模型要开跨域，中转站要确认支持浏览器调用。

等到超时：长剧本本来就慢，1~3 分钟正常；超过四分钟会被掐断，选小一档节点数再试。

返回的不是 JSON：它会自动让模型重写一次。两次都不行，就是模型不听话 —— 换一个，带结构化输出的模型通常更稳。

条件怎么写

条件框里写 变量 运算符 值，多个条件用 &&（并且）或 ||（或者）连起来：

  • 好感 >= 3　看过信 == true　路线 != "bad"
  • 好感 >= 3 && 看过信　（两个都成立）
  • 好感 > 5 || 结局 == "good"　（任一成立）
  • 名字 ~= "雨"　（~= 是「包含这段文字」，只对文字有意义）

运算符：>= <= > < == != ~=。值不加引号时按数字或布尔解析（3、true），加引号按文字（"good"）。只写一个变量名（如 看过信）表示「非 0 / 非空 / 非 false 即成立」。

条件不满足的选项，默认显示但变灰（让玩家知道「这里有别的路，只是你还进不去」）；勾上「条件不满足的选项直接隐藏」就完全不出现。想提示玩家缺什么，可以再放一句旁白。

素材库：传一次，所有作品共用

右侧「素材」面板现在分两块，别混：

区块存在哪 / 影响谁
素材库存在浏览器的 IndexedDB 里，所有作品共用。放几十张背景也不占剧本那 4.4MB 的额度；删掉会影响所有引用它的作品。
本作品素材跟着这个作品走，会被一起导出进 HTML，也占工程体积。

用法：素材面板顶部「上传素材」，一次可以选多张（图片和音频都收）。传进来之后，点一张 = 设为当前节点的背景；当前节点不是背景的话，会顺手替你在后面插一个背景节点。右上角 × 删除，铅笔改名 —— 名字会被 AI 看见，起得具体点，写「便利店·夜」比「IMG_0421」有用得多。

「管理」里能看总数和占用、批量改名、清空。上传的图不压缩、不转格式，原样存着 —— 反正不吃 localStorage 的额度。

导出的时候会发生什么

导出前，用到的那几张会从素材库里读出来、压成 dataURL 塞进 HTML，所以成品依然是「单个文件，双击就玩」。工程本身只存一个引用，几百字节。素材删了再导出，那一处会留空，并提示你有几张丢了。

导出与分享

  • 产物是单个 HTML：样式、引擎、剧本、图片全部压在一个文件里。不依赖这个站，也不依赖网络，拷到 U 盘、丢网盘、发群里都行。
  • 图片压缩三档：标准（长边 1600px，一般够用）／不压缩（原图，文件最大）／严格（长边 1080px，适合发群里）。PNG 会保持 PNG，不会被转成黑底 JPEG。导出前会显示预计体积。
  • 存档在玩的人本机：6 个手动槽 + 1 个自动存档，存在对方浏览器的 localStorage 里。你更新了作品重新发一份，对方旧存档里的节点索引可能对不上 —— 大改剧情前最好提醒一句。
  • 工程可以另存：菜单里有「导出工程 JSON」「导出全部作品」，换电脑或换浏览器时用它搬家。
  • 编辑期的存储有上限：工程存在浏览器 localStorage 里，整体约 4.4MB。上传的图片会先缩到长边 1920px（透明立绘转 WebP，透明不会被填黑），音频限 3MB；真的存不下时会明确提示并拒绝加入，不会把半截内容写进去。素材多了就拆成几个作品，或先导出 HTML。

几条实用建议

  • 立绘用透明背景的 PNG，人物脚底贴着画布下沿，同一角色的所有表情用同样的画布尺寸和站位，切换时才不会跳。
  • 没有图也能写：不填背景就是内置的深色渐变，立绘留空会显示占位框。先把剧情跑通，再补图。
  • 善用「等待」和「特效」：换场景前 淡出 → 等待 600ms → 换背景 → 从黑淡入，观感立刻不一样。
  • 大改之前导出一次 JSON。浏览器存储有上限，清了站点数据就没了。
  • 先写一条线，再补分支。分支一多，节点列表会很长，用「章节标签」分段会清爽很多。

  • 不支持视频和动态立绘（Live2D），只放静态图；视频可以自己用外链在背景里凑，但不会被一起打包。

把当前对话导出成一个可离线打开的 Galgame 页面，逐句播放、支持打字机与自动播放。可选「纯观看」或「可继续对话」：纯观看版不含任何 API 配置入口（设置面板里只有打字速度、字号、自动播放停顿等外观项）；「可继续对话」版自带独立的 API 设置，能在导出页里接着聊，新对话存在该页面自己的浏览器存储中。

最近聊过的角色排在前面

你和任意一个角色说过一句话，这个角色就会在列表里往前提。不影响置顶：置顶角色永远排在非置顶角色之前，同一分组内最近聊过的排最前，久未联系的自动沉下去。可在「设置 → 界面外观」关闭，恢复成完全固定的手动顺序。

文件消息（不再撑爆气泡）

发 .txt / .md 这类文本文件时，气泡里只会出现一张文件卡片（文件名 + 体积 + 行数），点开才是完整内容：可以滚动查看、一键复制、下载回本地。几百行的设定集发出去，聊天区也只多一张卡片。发给 AI 的仍然是全文，不会影响它读设定。

虚拟滚动（长对话性能）

对话消息超过 80 条时，聊天区只渲染当前可视区域附近的内容，DOM 节点数量大幅减少，长对话滚动更顺滑；消息较少的会话不受影响。开关在「设置 → 界面外观 → 虚拟滚动」，默认关闭；勾选后立即生效（自动重绘）并记住选择，如遇显示异常（空白、跳位），关掉开关即可恢复完整渲染。

角色列表拖动手感

调整角色顺序要先按住（触摸约 0.7 秒 / 鼠标约 0.34 秒），并且必须真的移动过一小段距离才会进入拖动状态 —— 所以普通点击与滑屏滚动都不会再把角色位置改掉。按住期间卡片会轻微收缩，提示「长按正在生效」。

？？？模式（高级动效）

开启后换成一套「播一次就停」的弹性动效：弹窗从被点的那个按钮里被拽出来、设置标签页弹性滑动、新消息逐条入场、按钮按压回弹。静止时不占用 GPU，因此不像旧版那样把页面拖卡。分「轻量 / 标准 / 丰富」三档，低端机建议先用轻量。

🧪 其它实验室与辅助功能

Code 模式(写代码)

开启后,单次回复的输出上限单独调高(默认 8192,最高 32000),不再被聊天设置里较小的上限截断;自动追加「给出完整可运行代码」之类的编码指令;并关闭消息分段,避免代码块被拆成好几条气泡;温度默认调到 0.3,让输出更稳定。适合让角色写完整的脚本或网页。

用户代码空间(两个界面)

在「设置 → 实验室 → 用户代码空间」里新建一个空间(如 myswuser1),之后访问 /myswuser1 就是一个属于你的小站点。它有两套界面,共用同一份代码,可随时切换:

经典版:全屏跑一遍 MySW 副本,顶栏「编辑代码 / AI」打开单文件编辑器,适合「先看效果、再手改几行」。工作台版:左边是多会话列表,中间和 AI 对话,右边是文件管理区与实时预览;AI 能直接读写工作区文件(先读后改、局部替换),改完预览会自动热更新,支持上传/拖拽文件、.zip 自动解压与整包导出。切换入口在空间顶栏和设置面板的每个空间一行。

上下文压缩器

聊天顶部的压缩按钮会打开面板,有三种方式:压缩「最近 N 轮」但保留最后 M 轮原文;在消息列表里勾选「第 X 条到第 Y 条」的范围压缩;或一次压缩除最近 M 轮以外的全部历史。压缩后会生成一条摘要消息替代原文,多次压缩时旧摘要会并入新摘要,不会越堆越多。

对话优化(Beta)

开启后,较长的角色提示词会被切成小块,每轮只下发与当前话题最相关的几块(默认最多 4 块);提示词较短(默认 600 字以下)时仍整体下发。可以节省 Token,但某些轮次里冷门的设定细节可能不会出现,遇到角色「忘事」时可以关掉它对比。

缓存优化

在「设置 → AI 配置 → 缓存优化」里按站点选择策略。它把系统提示里每轮都会变化的内容(时间戳、随机 ID 等)挪到用户消息里,让前缀尽量保持一致,从而命中服务商的前缀缓存;并按平台(DeepSeek、Kimi、OpenAI、Claude)附加对应参数。默认关闭,关闭时请求与之前完全一致。命中情况可在「界面外观」里查看统计。

AI 属性调节器

在「设置 → AI 配置 → AI 属性调节器」里给角色装一组能拧的旋钮：内置智商、情商、傲娇程度、猫耳大小、猫尾巴长度五项（默认都不启用），也可以新增自定义属性，并改名字、上下限、数值，或用「重置属性」恢复内置五项。每个数值都会被翻成一句人话写进系统提示词——智商 100 是「普通水平，偶尔犯迷糊」，调到 165 就变成「非常聪明，能听出话里的漏洞」。「自动调节」让数值每轮小幅波动，「AI 调节」允许模型在回复末尾用隐藏标记（[[attr:智商=+10]]）改动属性，标记会被自动摘掉，不会出现在气泡里。作用对象可以选全局默认，也可以给单个角色单独一套。效果最终取决于你用的模型，同一组数值换模型可能完全是另一个样子；展开「这段会怎么发出去」能看到真正发出去的原文。

🧭 查看存储使用情况

位置在「设置 → 导入导出」标签的导入导出按钮下方：点「查看存储使用情况」打开面板明细；边上的「重新统计」只重算体积、不重建面板，所以不会把你已经勾选的项清掉，统计期间的瞬时建库也不会留下空壳数据库。

  • 一眼看总量：顶部进度条与四张卡片给出「浏览器统计的总占用 / 本站可用配额 / IndexedDB 合计 / localStorage 合计」，以及各类缓存（Cache Storage，主要就是离线资源）占了多少。
  • 按用途分列：下面按库分组列出 localStorage、主数据库 MySW_Storage、以及知识库 / 实验室 / 论坛 / 启动画面等独立 IndexedDB 库，每个库再展开到具体条目，条目同时给出「存了哪些 key」。
  • 标出「可再生」与「不可再生」：聊天记录、角色数据、论坛内容、知识库这类删了就回不来的条目会打上红色的「不可再生」标签；提示词分块缓存、折叠状态、商店缓存这类随时能重建的才是「可再生」。
  • 两道确认，删不掉聊天记录：勾选条目后点「清理选中」，可再生项只要确认一次；只要列表里含不可再生项，就必须在弹出的框里手动输入 DELETE 才会执行，防止顺手把聊天记录清空。想更保险，可以先把「导出全部数据」存一份再动手。
  • 一键清理可再生数据：一次清掉所有「可再生」条目并顺带清空 Service Worker 缓存刷新页面，绝不会碰不可再生条目。
关于浏览器存储

本应用的数据存储在浏览器的 localStorage 和 IndexedDB 中。这意味着：

  • ❌ 清除浏览器数据 = 数据全失。请定期导出备份！
  • ❌ 不同浏览器、不同设备、不同浏览器配置文件之间数据不互通。
  • ✅ 隐身模式下数据不保留（这是浏览器的特性）。

🎛️ 功能开关（按功能关，不用认文件名）

位置在「设置 → 功能开关」。这里把每个 js 模块翻译成一句人话（「广告跳跳乐」「视觉小说模式」「五子棋与围棋」…）， 直接按功能关，不用去猜哪个文件名对应哪个功能。它和「加载 JS 文件设置」是同一份开关，在哪边改都一样。

  • 三种关掉后的效果：
    • 独立文件（广告跳跳乐、学习辅导、森林冰火人、AI 直播间…）：刷新后这个 js 真的不再下载。
    • 同包功能（标着「同包」的，比如视觉小说、好感度、代码高亮）：合并包本身还会下载（别的功能还在用），但这个功能的代码不再运行。
    • 核心功能：锁死，只有锁图标，没有开关。
  • 核心为什么锁死：渲染、对话、设置读写、API 这些是地基。关掉主程序页面就直接白屏；关掉设置读写，你连这个面板都打不开。所以整组显示为「N 项锁死」，点开只能看，不能改。
  • 这个面板自己也锁死：它的宿主是 script-loader.js，标着「面板自身」。真把它关了，你就再也调不回来 —— 所以它永远加载，写进存档也会被忽略。
  • 依赖会被锁定：有些功能要别人配合。比如关掉「视觉小说模式」，「VN Live2D 立绘」就会显示 🔒 并说明原因；关掉「语音合成」，「语音通话」跟着锁。想用就先把被依赖的那项打开、刷新，再回来调。
  • 关掉的功能入口会自己解释：广告、3D、学习辅导这类入口还留在原地，但点下去会弹一句「这个功能被关掉了 · 要恢复：设置 → 功能开关 → 打开 X → 刷新」，不会让你以为按钮坏了。
  • 改动即时保存：这一页没有「保存」按钮，拨动开关就立刻写进本机，页面顶部会出现「刷新后生效」+ 立即刷新。

🧩 加载 JS 文件设置

位置在「设置 → 导入导出」，紧挨在「查看存储使用情况」下面。点「加载 JS 文件设置」打开列表面板；边上的「恢复全部加载」一键把所有可关闭的脚本重新打开。

  • 按用途分组：基础库、核心、增强、实验室、外观。每一行都写着文件名，以及关掉之后具体少掉什么功能。
  • 必须加载的锁死：角色数据、AI 接口、主程序、聊天逻辑、世界书、知识库、设置读写等标着红色「必须加载」，开关是灰的。这些关掉后聊天、角色或设置会直接不可用。
  • 可关闭的不影响数据：代码高亮、ZIP 打包、开屏、语音、插件、视觉小说、3D 实验室、五子棋、好感度等可以单独关掉。关掉只是下次打开时不再下载对应脚本，不会删除聊天记录、角色或已保存的设置。
  • 两个快捷按钮：「全部加载」恢复默认；「只留必须加载」关掉全部可选功能，只保留能正常聊天的那一部分。
  • 刷新后才生效：选择存在本机浏览器里。保存之后点「立即刷新页面」，已经在跑的脚本才会真正卸掉。换设备或清除网站数据后会回到全部加载。

🔄 刷新网站

位置在「设置 → 更多」，使用文档和反馈邮箱的上面。从温和到彻底一共四档，都不会删除聊天记录、角色和设置（那些存在本机浏览器里，不在离线缓存中）。

  • 1 · 重新加载：相当于按一下浏览器的刷新键。适合刚改完设置，或界面暂时卡住。
  • 2 · 绕过页面缓存：效果接近电脑上的 Ctrl+F5（Mac 为 Cmd+Shift+R）。地址后面会带一次不重复的标记，强迫浏览器重新要这一页。
  • 3 · 清掉离线缓存后重载：删掉 Service Worker 存下的脚本、样式和图标，再重新下载。手机下拉刷新清不掉旧版本时用这个。清完之后、再次联网之前，离线打开会暂时不可用。
  • 4 · 卸载并重新安装：最彻底。会先确认一次，然后注销离线服务、清空它的全部缓存，再把页面从网络装回来。前三档都没用、页面一直停在坏掉的旧版时再用。

点下去之后按钮会暂时锁住并改成「正在…」，避免连点。这次刷新不会顺带触发自动备份下载，以免下载框把页面刷新挡住。

⏱️ 急死我了（AI 催你回话）

默认情况下，你消失三个小时再回来，角色会像什么都没发生一样接着上一句聊下去。急死我了专门治这个：它记住「AI 说完那句话之后，你隔了多久才回」，等得越久，下一次回复时角色越坐不住——会催、会阴阳怪气、会来一句「这么久才回我」。

在哪开

它是内置插件，不用下载：在「系统设置 → 插件」里找到「急死我了」，勾上「启用」，改完参数点「保存参数」。关掉之后计时和注入会一起停掉，聊天记录不受影响。

它到底做了什么

  1. 记时间AI 每说完一条回复，记一个时间点。数据只存在你本机，刷新、关浏览器、隔天再打开都还在。
  2. 算间隔你下一次发消息时，算出中间隔了多久（每段对话单独算，切角色不会串）。
  3. 写进提示词把间隔折算成「烦躁等级 0~4」，往系统提示词末尾追加一小段：你等了多久、此刻该有多急。模型看到的是「等了 12 分钟 · 明显不耐烦」，不是一串秒数。
  4. 说完就归零AI 一开口，计时清空，下次重新算。所以它只影响「你隔了很久才回」的那一条回复。

四个参数

参数默认怎么调
倍率10.2 ~ 5。越高越早开始急：倍率 2 等于所有等待时间减半，倍率 0.2 基本等于永远不急。想整站更黏人，先动它。
基准等待（秒）90倍率为 1 时，等多少秒才进入「有点等急了」。设 30 就是半分钟开始催，设 600 就是十分钟。
含蓄模式0填 1：只暗示、不点破，不会出现「你怎么才回我」这种直球。适合冷淡型角色或不想被催得太明显的时候。
角色单独系数空一行一个：雷狮=1.6、银狼=0.5。大于 1 更容易急，小于 1 更沉得住气，写 0.1 基本等于对他关掉这个功能。

性格不同，急的程度也不同

同样是等了 10 分钟，急性子和冷淡型不该是一个反应。插件按三级决定「多久才算久」，优先级从高到低：

  • 角色单独系数（手写，最优先）：按显示名匹配，写什么就是什么。
  • 人设关键词：角色设定里出现「急性子 / 暴躁 / 没耐心 / 等不及」这类词会自动抬一档；出现「冷静 / 沉稳 / 慵懒 / 寡言」会自动压一档。写人设时把性格写清楚，这里就不用管了。
  • 倍率 × 基准等待：全局总开关，所有角色一起变。

换算下来，急性子角色可能一分钟就开始念叨，冷淡型角色要等到十倍时间才有点动静——差异是自动出来的，不用给每个角色单独配。

四个烦躁等级

等级大致触发（倍率 1 / 基准 90 秒 / 性格系数 1）注入给 AI 的意思
090 秒以内不注入，正常回复。
11.5 ~ 4 分钟有点等急了：语气短一点，可以透出一句「你可算回来了」，但不追问。
24 ~ 10 分钟明显不耐烦：先问一句刚才在忙什么，可以催、可以有小情绪。
310 ~ 22 分钟快没耐心：语气变冷变冲，允许阴阳怪气或直白抱怨。
422 分钟以上已经不想等了：冷战、赌气、发火、装作不在意，按人设自己选。

输入框上方的小浮标

AI 说完话之后，输入框上方会出现一个小条：已等 3 分 12 秒 · 明显不耐烦，右边四个小格表示当前等级，等级越高颜色越红。它只负责显示，不影响任何发送逻辑。

浮标要在「设置 → 插件 → 插件权限」里打开「直接修改页面」才会画出来（插件本身不需要任何权限就能工作，只是看不到这个倒计时）。不想看到它就别开这个总闸。

三个预期

它是提示词，不是硬逻辑。模型听不听话、演得多夸张，取决于你用的模型、上下文长度和人设写得多细。同样的等级，Claude 可能给你一段细腻的赌气，小模型可能只是回一句「哦」。

不要在角色卡里和它打架。如果人设里写着「永远温柔耐心、从不催促」，急起来就会很割裂——这时候把「含蓄模式」设成 1，或者把该角色的系数调到 0.5 以下。

群聊同样生效。群里任意一个成员说完话就开始计时，所有人共享同一个间隔。

🔌 插件编写指南

市场里现在有 11 个插件，其中 6 个是「装上就能改善体验」的实用型

去插件市场，把主站开在任意标签页，点卡片上的「一键导入」——主站会弹出确认框（显示来源、插件标识与它要的权限），确认后就装好了，不用下载也不用找文件。主站没开或换了浏览器时，市场页会在 1.6 秒后自动改为下载 .js，再按老办法从「设置 → 插件 → 导入插件」装。下面是目前的清单：

  • 角色一致性守卫：拦住「替用户说话 / 替用户行动 / 一句话跳过半天 / 末尾写总结」，规则可逐条编辑（无需权限）。
  • 去 AI 味：去掉「首先其次最后」「作为一个 AI」这类一眼假的句式，三档强度，可单独禁 emoji（无需权限）。
  • 回复长度限幅：把每轮回复卡在指定字数区间，治长篇大论与一句话敷衍（无需权限）。
  • 提示词体检：左下角常驻显示当前提示词的字数、估算 Token 与每轮成本，点开可复制全文（需 useDom）。
  • 设定速记本：随手记「她其实怕黑」这类临时设定，每轮自动注入，不用去改角色卡（需 useDom）。
  • 快捷短语板：常用句存成列表，点一下插进输入框光标处，不会直接发送（需 useDom）。

前三个只改提示词，不需要任何权限；后三个要在「插件权限」里打开「修改界面 / DOM」并给该插件单独授权，按钮才会出现。

My SW 自带一个轻量插件系统：一个插件就是一个 JavaScript 文件，通过全局对象 window.MySWPlugins.register() 注册自己。插件能改你发出去的文字、能给 AI 追加提示词、 能在聊天界面里挂一个面板，也能借用你配置的 API 发请求 —— 但每一项都必须你显式授权，插件不能通过受控接口拿到 Key。

先看安全模型

导入的插件默认跑在受限沙箱里：代码里拿不到 document、window、 localStorage、fetch，只能用下面列出的受控通道。要什么能力，你在 「设置 → 插件 → 插件权限」里逐项开。默认全部关闭。

权限与沙箱：插件到底能碰什么

权限拆成了 8 项，每项都写清楚「开了会怎样」。插件要用的能力要在 permissions 里声明， 你在权限面板里开总闸，再在插件卡片上决定要不要单独授给它。

权限插件能做什么说明
ui加按钮 / 悬浮面板 / 确认框推荐的界面方式：插件只描述「要一个按钮」，元素由系统创建，卸载时自动清理。插件碰不到页面 DOM。
dom直接改页面元素和样式高风险。老插件（悬浮小窗口那类）需要它；写错可能把界面弄乱。关闭时会清掉插件插进去的元素。
chatRead读取当前对话内容只读。开了它，插件就能看到你和角色聊了什么。
chatWrite往对话里插入 / 修改消息会影响之后发给 AI 的上下文，属于高风险项。
storage读写插件自己的存储命名空间隔离（pluginData:<插件id>:），单插件上限 64KB，看不到站点数据。
api借用「AI 配置」里的接口可能产生 token 费用；插件拿不到 Key 明文，只能走受控方法。
network访问任意 http/https 地址高风险。开了它，插件可以把数据发到外部服务器。
download触发下载导出插件产生的数据。

除了权限，插件卡片上还有两个东西值得看：

  • 代码体检：注册时静态扫一遍源码，发现「用到了 localStorage / fetch / document 但没声明对应权限」就标黄提醒。它看不出插件想干什么，但能告诉你它碰了什么。
  • 调用记录：插件每次走受控通道（读对话、写对话、联网、下载、存储）都会记一笔， 在卡片上展开就能看「谁、什么时候、调了什么」。只存在内存里，刷新即清空。

需要说明的是：沙箱能挡住插件的误用和顺手越权，但它不是浏览器级隔离—— 恶意代码仍可能用 eval 之类的手段绕出去。所以最实际的防线还是：别装来路不明的插件。

最小可用插件

新建一个 .js 文件，内容如下，然后在「设置 → 插件」里把这个文件导入即可：

// hello-plugin.js
MySWPlugins.register({
    id: 'hello-shout',
    name: '喊话器',
    description: '把你发出的每条消息都变成全大写（英文）并在结尾加感叹号。',
    permissions: [],           // 只做文本变换，不需要任何权限
    params: [
        { key: 'mark', label: '结尾标记', type: 'text', value: '！' }
    ],
    // 文本变换钩子：用户按发送 → 先过这里 → 再存进聊天记录并发给 AI
    transformText(text, params) {
        const mark = String(params.mark || '！');
        const upper = String(text || '').toUpperCase();
        return upper.endsWith(mark) ? upper : upper + mark;
    }
});

保存后导入，插件会出现在列表里但默认是未启用状态，勾上「启用」才开始生效。

register() 的字段

字段类型说明
idstring必填。唯一标识，重复注册时后者覆盖前者。建议用短横线小写，如 my-weather。
namestring必填。显示在插件卡片上的名字。
descriptionstring一句话说明，会显示在卡片上。
permissionsstring[]声明需要的权限，取值只能是 'useApi' 与 'useDom'。不写会被保守视为需要 useDom。
paramsobject[]可编辑参数，每项形如 { key, label, type, value, min, max }。类型支持 text / number / textarea（长文本，如提示词）。
enabledboolean初始启用状态。建议写 false，让用户自己决定何时开启。

权限系统（两级授权）

权限只有在总开关与该插件的独立授权同时打开时才生效，两者是 AND 关系。

  • 总开关：设置 → 插件 → 插件权限。默认关闭，关掉即对所有插件生效。
  • 插件授权：每个插件卡片上的勾选框，默认已勾选 —— 所以你只需要拨一次总闸，插件立即可用；想只信任某一个插件时，把其它插件的授权单独收回即可。
权限能做什么明确不能做什么
useApi通过 ctx.api.chat() 借用你的接口发请求；可读模型名与端点域名。拿不到 apiKey 明文；不能读你的聊天记录。
useDom把元素挂到聊天界面；读取页面元素。关闭权限或停用插件时，系统会强制移除它挂过的所有节点。

插件内部可用 MySWPlugins.hasPermission('useApi') 查总开关，用 MySWPlugins.canPluginUse('my-id', 'useDom') 查最终生效结果，做优雅降级而不是直接抛错。

四种钩子：什么时候会被调用

钩子触发时机用途
activate启用插件、或权限刚被授予时挂面板、启动定时器
deactivate停用插件、权限被收回、删除插件时清元素、清定时器
transformText你按发送之后、消息入库之前（单聊与群聊都会走）加口癖、做文本替换、敏感词处理
transformPrompt系统提示词拼好之后（世界书 / 记忆 / 时间之后，表情包说明之前）追加扮演指令、风格约束
钩子必须幂等

transformPrompt 在一轮对话里可能被多次调用，而重发、重新生成也会再走一遍。 追加内容前请先判断是否已包含，否则提示词会越叠越长：

transformPrompt(text, params) {
    const extra = String(params.prompt || '').trim();
    if (!extra) return text;
    const base = String(text || '');
    if (base.includes(extra)) return base;   // 幂等：只追加一次
    return base + '\n\n' + extra;
}

任何钩子里抛出的异常都会被捕获并记录到控制台，不会影响正常对话 —— 单个插件写崩了最多是自己不生效。

受控 API 通道：借用接口但不接触密钥

ctx.api 是唯一允许插件发起模型请求的入口，每次调用都会实时校验权限，你在设置里一关就立刻失效。

成员说明
ctx.api.availableboolean，权限是否可用且接口已配置。推荐先用它做降级判断，而不是捕获异常。
ctx.api.getInfo()返回 { model, hasKey, endpoint }，其中 endpoint 只有域名，用于显示「正在使用 xxx」。
await ctx.api.chat(messages, overrides)一次性补全，直接返回字符串。适合翻译、摘要、分类等场景。
await ctx.api.fetchChat(messages, overrides)返回原始 Response，需要流式或自解析时使用。
 
async activate(params, plugin, ctx) {
    if (!ctx.api.available) {
        // 没授权 / 没配置接口 → 优雅降级，别报错吓用户
        ctx.toast('本插件需要「使用 API 配置」权限');
        return;
    }
    const info = ctx.api.getInfo();
    console.log('使用模型：', info.model, '端点：', info.endpoint);

    const answer = await ctx.api.chat([
        { role: 'system', content: '你是一个简洁的翻译助手，只输出译文。' },
        { role: 'user', content: '把下面这句话译成英文：今天天气不错。' }
    ], { max_tokens: 200 });
    console.log(answer);
}

受控 DOM 通道：挂界面能被统一回收

不要直接 document.body.appendChild()。用 ctx.dom.mount(node, container) 挂载， 系统会登记这个节点，在插件停用或权限被收回时自动移除，界面能干净复原。

成员说明
ctx.dom.availableboolean，是否有界面权限。
ctx.dom.mount(node, container)把元素挂到 container（默认聊天区 #chat-area）并登记。
ctx.dom.unmountAll()立即移除本插件挂过的全部元素。
ctx.toast(message)弹出应用内提示，比自己写 alert 体面得多。
 
permissions: ['useDom'],

activate(params, plugin, ctx) {
    if (!ctx.dom.available) return;
    if (document.getElementById('my-clock-panel')) return;  // 幂等：避免重复挂载

    const panel = document.createElement('div');
    panel.id = 'my-clock-panel';
    panel.style.cssText = 'position:absolute;right:16px;top:16px;padding:8px 12px;border-radius:10px;' +
                          'background:rgba(20,22,30,.86);border:1px solid rgba(230,199,138,.4);color:#e6c78a;font-size:.82rem;z-index:20';
    panel.textContent = new Date().toLocaleTimeString();

    const timer = setInterval(() => { panel.textContent = new Date().toLocaleTimeString(); }, 1000);
    panel._timer = timer;

    ctx.dom.mount(panel);              // 交给系统登记，停用时会被自动移除
},
deactivate() {
    // 定时器必须自己清：系统只负责移除元素，不会管你开的计时器
    const panel = document.getElementById('my-clock-panel');
    if (panel?._timer) clearInterval(panel._timer);
}

ZIP 插件包资源（ctx.assets）

ZIP 导入的插件可以带自己的资源文件。除了约定的 style.css 会自动注入（受「界面」权限管），其余资源都是惰性数据，插件在运行时用 ctx.assets 按相对路径读取自己名下的文件（不带插件文件夹前缀）：

方法返回说明
await ctx.assets.list()string[]自己名下全部资源路径，如 ['style.css', 'assets/logo.png', 'data/words.json']。
await ctx.assets.getText(path)string | null读文本资源（json / css / md / txt / csv / xml / html），没有时返回 null。
await ctx.assets.getUrl(path)string | null读二进制资源（图片 / 字体 / 音频等），返回 Object URL（可直接塞进 img.src），没有时返回 null。

安全边界：资源在导入时就经过类型与体积检查（单文件 512KB、单插件总量 4MB），只存不执行；getUrl 给的是本地 blob 链接，不产生网络请求。删除插件时资源一并删除。

导入、调试与本地存储

  • 导入：设置 → 插件 → 「导入插件」，选择一个 .js 文件，或一个 ZIP 插件包（可一次导入多个插件，见下条）。文件内容会被包进 new Function('MySWPlugins', code) 执行，因此插件里必须用全局的 MySWPlugins.register() 注册，而不是 ES 模块的 export。
  • ZIP 插件包：压缩包里每个插件一个文件夹，文件夹里放一个含 MySWPlugins.register(...) 的 .js 入口（文件名随意）；可选 style.css（插件启用且有「界面」权限时自动注入，关闭时自动移除）；其余文件作为惰性资源供插件的 ctx.assets.getText(path) / ctx.assets.getUrl(path) / ctx.assets.list() 读取。导入时会列出包里找到的所有插件，勾选要装哪几个；与已安装插件同 id 时标记「覆盖已安装」，覆盖会保留你原来的开关、授权与参数。直接把单个 .js 放在压缩包根目录也可以。
  • ZIP 包的安全边界：只有通过 register 闸门的入口 .js 会被执行（和单文件导入同一标准）；其余文件永远只当数据存进 IndexedDB，不会被执行、不会被注入成脚本或样式表（style.css 除外，且受「界面」权限管）；嵌套压缩包、可执行扩展名、含 ../ 或绝对路径的条目一律拒绝；文件数量与体积设多重上限防 zip 炸弹。
  • 持久化：导入的插件源码与参数存在 localStorage 的 mySWPlugins 里，ZIP 附带的资源存在 IndexedDB 的 myswPluginAssets 库里；刷新后自动重新加载，删除插件时源码与资源一并清除。
  • 参数：参数值存在插件记录里，改完要点卡片上的「保存参数」。读取时通过钩子的 params 参数拿到，不要自己去读 localStorage。
  • 调试：用 console.log 输出到浏览器控制台；钩子里的异常会以 [插件名] xxx 失败 的形式打印警告，直接搜索插件名就能定位。
  • 排查顺序：插件不生效时，先看卡片上有没有黄色提示条（说明权限没给全），再看控制台有没有报错，最后确认 id 是否与已有插件重复。
  • 导出：自己导入、或用 AI 写好再导入的插件，卡片上有「导出」。它导出的是当初保存下来的源码，不是运行后的状态。

用 AI 编写插件

位置在「设置 → 插件」，导入按钮下面有一块默认收起的折叠板「用 AI 编写插件」。

  • 模型：模型框留空就用当前聊天模型；填了名字则固定用这个模型，不再跟着站点切换。
  • 怎么写：用一句话描述想要的效果，点「生成插件」。代码先出现在文本框里，可以手改。

示例一：翻译按钮（API + DOM 权限，把最后一条 AI 回复译成中文并弹出来）

MySWPlugins.register({
    id: 'quick-translate',
    name: '一键翻译',
    description: '在聊天界面加一个悬浮按钮，把最后一条 AI 回复翻译成中文。',
    enabled: false,
    permissions: ['useApi', 'useDom'],
    params: [
        { key: 'target', label: '目标语言', type: 'text', value: '简体中文' }
    ],
    activate(params, plugin, ctx) {
        if (!ctx.dom.available) return;
        if (document.getElementById('quick-translate-btn')) return;

        const btn = document.createElement('button');
        btn.id = 'quick-translate-btn';
        btn.type = 'button';
        btn.textContent = '译';
        btn.title = '翻译最后一条 AI 回复';
        btn.style.cssText = 'position:absolute;left:16px;bottom:88px;width:40px;height:40px;border-radius:50%;' +
                            'border:1px solid rgba(230,199,138,.5);background:rgba(20,22,30,.9);color:#e6c78a;' +
                            'cursor:pointer;z-index:20;font-size:1rem';

        btn.addEventListener('click', async () => {
            if (!ctx.api.available) { ctx.toast('需要「使用 API 配置」权限'); return; }

            // 取最后一条 AI 消息（.message.other 里的气泡文本）
            const bubbles = document.querySelectorAll('#chat-messages .message.other .bubble');
            const last = bubbles[bubbles.length - 1];
            const source = last ? last.innerText.trim() : '';
            if (!source) { ctx.toast('还没找到可翻译的 AI 回复'); return; }

            btn.disabled = true;
            btn.textContent = '…';
            try {
                const target = String(params.target || '简体中文');
                const result = await ctx.api.chat([
                    { role: 'system', content: '你是翻译引擎，只输出译文本身，不要任何解释。' },
                    { role: 'user', content: '把下面内容翻译成' + target + '：\n' + source.slice(0, 2000) }
                ], { max_tokens: 800 });
                ctx.toast('译文已输出到控制台');
                console.log('[一键翻译]\n' + result);
            } catch (e) {
                ctx.toast('翻译失败：' + (e.message || e));
            } finally {
                btn.disabled = false;
                btn.textContent = '译';
            }
        });

        ctx.dom.mount(btn);
    },
    deactivate() { /* mount 过的节点由系统统一回收 */ }
});

示例二：风格约束器（零权限，纯提示词注入）

MySWPlugins.register({
    id: 'style-guard',
    name: '回复风格约束',
    description: '给 AI 追加一条固定规则，比如「每次回复不超过 3 句话」。',
    enabled: false,
    permissions: [],           // 纯提示词变换，不需要授权
    params: [
        {
            key: 'rule',
            label: '要追加的规则',
            type: 'textarea',
            value: '【风格约束】请把每次回复控制在 3 句话以内，不要分点罗列，不要输出 Markdown 标题。'
        }
    ],
    transformPrompt(text, params) {
        const rule = String(params.rule || '').trim();
        if (!rule) return text;
        const base = String(text || '');
        if (base.includes(rule)) return base;   // 幂等
        return base + '\n\n' + rule;
    }
});
写好插件的三条经验
  • 声明最小权限：纯文本钩子不需要任何权限，就别写 permissions（未声明会被当成需要 DOM）。
  • 一切都是异步的：activate 与所有钩子都可能被并发调用，加实例标记做幂等，别让同一个面板挂两次。
  • 不假设 DOM 永远存在：用户可能切走角色、清空聊天、切到视觉小说模式，取元素时统一用可选链。

📺 广告跳跳乐（实验室）

在「设置 → 实验室 → 广告跳跳乐」开启的模拟广告体验：开屏、摇一摇、弹窗、banner、浮标、内容广告六种形式， 广告内容全部由你自己配置（文字 + 图片/视频素材），不接任何广告联盟、不上报任何数据、素材只存本机。

它不是广告

所有模拟广告上都会带一行小字标注：「实验室模拟广告 · 你自己开的 · 不是 MySW 在圈钱」。这个功能纯属好玩/自嘲/整活，与真实的广告投放没有任何关系。

能配什么

  • 生效的广告形式：开屏（打开页面来一下）/ 摇一摇（手机重力传感器触发，桌面端可在管理面板手动测试）/ 弹窗（进页面一段时间后弹一次，间隔可调）/ banner（页面顶部横幅）/ 浮标（右下角 AD 小浮标，点开展开）/ 内容广告（混进内容流，见下）。
  • 生效场景：主站（聊天 / 实验室 / 学习辅导）、论坛、文档、角色市场 / 插件市场，逐个勾选。默认四个页面全开 —— 若只在主站勾上，去论坛或插件市场会觉得「开了广告却什么都没有」。
  • 内容广告：不浮在页面之上，而是像一条真实内容那样插进列表里，每页只插一条，带金色「广告」角标和虚线边框（一眼能看出不是真内容）。插入位置按页面语境决定：
    • 论坛 → 帖子列表中间（第二条帖子之后）
    • 主站聊天 → 消息流里（第一条消息之后）
    • 文档 → 章节之间（第二个 h2 之前）
    • 插件市场 → 插件网格里（第三张卡片之后）
    列表是 JS 渲染的，所以广告会在列表出现后几秒内补进去：前 20 秒每 400ms 查一次，之后每 3 秒查一次，最多守 8 分钟。列表一直是空的（新会话、空论坛、筛选后没结果）时会插在容器最前面，不会因为「没有锚点」就什么都不显示。 论坛切分类、插件市场换筛选会把列表整个重绘，广告被冲掉后会自动补回来（用户自己点 × 关掉的不补，最多补 12 次）。
  • 广告内容：想加几条加几条。每条可填标题与文字、上传一张图片（≤5MB）或一段视频（≤30MB）。
  • 一条广告出现在哪些形式里：每条广告单独勾「会出现在」哪些形式 —— 同一张图可以同时用于开屏和 banner，互不冲突。
  • 生效场景 per 广告：每条广告还可以单独限定只在某些场景出现（比如只在论坛弹）。
  • 播放顺序：随机，或按列表依次轮播（列表可上移/下移调整顺序）。
  • 关闭按钮大小：预设小 18px / 中 26px / 大 38px，也可以直接填任意 px（6 ~ 180）盖过预设，对开屏、弹窗、banner、内容广告统一生效。
  • 弹窗间隔：5 ~ 3600 秒。弹窗每次打开页面只会自动弹一次，不刷屏。

流氓设置（阴阳国软）

一组照着某些国产 App 祖传手艺做的开关，默认全关，只作用于你自己配的模拟广告。想体验被恶心是什么感觉，勾上就行：

  • 迷惑 ×：广告角上多出 1~6 个大 ×，全是假的。点假 × 有三种反应：提示「关闭失败，请稍后再试」／毫无反应／再给你推一条。真 × 可以选「缩成一粒灰」，最多 14px、半透明，缩在右下角（自定义尺寸填得更小就按更小的来）。
  • 不感兴趣：广告上出现「不感兴趣」按钮。点完之后有两种算法：
    • 推荐更多这类（默认，B 站式）：每点一次，这条广告被抽中的权重 ×5，而且关掉 2.6 秒后自己弹回来 —— 越点越推。
    • 减少这类：正常人的做法，权重按 1/(1+点击次数) 衰减，关掉就真关掉。
    点过的次数会记在广告上，管理面板里能看到「👎N」。
  • 广告标识：可以整个关掉（广告上就再也没有「广告」两个字了），也可以改字号（8~24px）和文字内容。底部那行「实验室模拟广告 · 你自己开的 · 不是 MySW 在圈钱」不受影响，永远在。
  • 假头发丝：屏幕上常驻 1~6 根半透明发丝，模拟「屏幕脏了」的错觉。鼠标从旁边划过去，它会被拨开、松手再弹回原位，但永远擦不掉 —— 你就是会忍不住去擦。浓度可选淡 / 中 / 浓。它是固定层 + SVG，不吃任何指针事件，不挡点击、不挡输入，也不占额外存储。
  • 跳转套娃：点掉一个弹窗，70 毫秒后原地又冒一个。× 每层小 3px、位置还乱偏；默认第 4 层放行，勾「真的无限」会一直套下去（第 12 层强制放行，免得真把你锁死在页面里）。任何时刻按 Esc 一次性全关掉。
  • 评论区 / 水军（每条广告单独设）：给广告挂一个评论区，显示一个几千条的假总数。开启「放水军」后才会有内容，水军数量 1~12 条，话术可以自己填（每行一条），留空就用内置那套（已经买了孩子很喜欢 / 蹲个链接 / 我妈用了都说好 ……）。不开放水军时评论区显示「还没有评论，来抢沙发」。

水军是纯前端随机拼装的：昵称由两段词根组合，正文从话术池里抽，头像是一个随机色圆形。不调用任何模型、不消耗 token —— 没人想边被折磨边烧钱。「换一批」就是重新抽一遍。

数据与开关

  • 配置存 localStorage 的 mySWLabAdsConfig；图片/视频以原始文件存 IndexedDB 的 myswLabAds 库，删广告时素材一并删除。
  • 引擎是独立的 ad-lab.js，主站 / 论坛 / 文档 / 角色市场 / 插件市场各页面都会引用；功能关闭时它什么也不做，不注入任何东西。
  • 摇一摇依赖 devicemotion：iOS 需要在管理面板触发一次授权；桌面没有传感器就不会触发，用「立即摇一摇」按钮测试。触发有 8 秒节流。
  • 开了却看不到广告？点管理面板左下角的「诊断」，它会列出当前页面识别成哪个场景、每一页形式开关、该形式下有几条可用广告、内容广告的锚点找到了几个。哪一行是 × 就是卡在哪一步。九成情况是「形式开了，但没有广告勾这个形式」或者「该广告的生效场景没包含这一页」。

💗 好感度系统（实验室）

在「设置 → 实验室 → 好感度」开启后，每个角色会单独拥有一条情感进度条。它的作用不只是显示一个数字： 系统会把当前阶段对应的相处准则一并写进发给 AI 的提示词，因此好感度越高，角色确实会对你更亲近、也更愿意接受更深入的互动。

它是怎么涨的

每完成一轮有效互动（你发出消息 → 角色成功回复）结算一次，计算公式为：

本轮增量 = (基础增量 + 随机浮动 × random) × 档位衰减^当前档位序号 × 角色倍率
然后再受「每人每日上限」与「同一角色冷却时间」限制
  • 基础增量：每轮固定加多少，默认 2。
  • 随机浮动：额外随机加 0 ~ 该值，让进度有一点起伏。
  • 档位衰减：默认 0.85。档位越高涨得越慢 —— 调小它会让后期更难涨（更耐玩），调成 1 则每档速度一致。
  • 每日上限：防止一口气刷满。设为 0 即不限制。
  • 冷却时间：同一角色多久内只结算一次，默认 45 秒。
  • 自然衰减：长期不聊会慢慢变淡。默认「1 天不聊后每天掉 1 点」，调成 0 即可完全关闭衰减。
  • 角色倍率：只想让某个角色涨快或涨慢时，单独给它设 0.1 ~ 3 的倍率。

档位与相处准则

默认提供五个档位（初识 / 熟识 / 亲近 / 亲密 / 挚爱），每个档位都可以自己改名、改起始值、改准则文本：

档位默认起始值默认准则大意
初识0礼貌、克制、有距离感，越界的请求会自然婉拒
熟识20可以开玩笑聊日常，暧昧话题上会害羞、打岔
亲近45重要朋友，主动关心、更亲昵的称呼、更放松的内容
亲密70明显越过普通朋友，允许暧昧与肢体亲近的描写
挚爱90可以放下掩饰主动表达爱意，但仍保留角色本身的性格与底线

建议在准则里写清楚这个阶段允许到什么程度。写得太笼统，角色可能一上来就越界；写得太保守，则会永远停在最拘谨的状态。 准则会随对话动态下发，所以改完保存，下一轮对话立刻生效。

查看与管理

  • 聊天界面角色名字旁会显示一枚心形徽标：数字是当前好感度，长按或点击可打开进度面板。
  • 面板里可以查看每个角色的进度与最近 10 条变化记录，也能手动 ±5 或重置。
  • 群聊中按「成员 × 用户」分别结算 —— 同一个群里，不同角色对你的亲近程度可以完全不同。
  • 好感度只保存在本机 localStorage，随「导出全部数据」一起备份。

⚫ 五子棋与围棋（实验室）

在「设置 → 实验室 → 棋局」里可以和当前打开的单个角色下棋。群聊不能直接开始，先切回一个普通角色。

  • 左边是聊天。可以边下边说话，角色会按自己的人设接话：人设里爱吐槽的可能会嫌弃你下的那一步，温和的角色就正常聊天。这一栏自带滚动条，聊天记录多了也不会把棋盘顶走。
  • 中间是棋盘。点空格就是在那里落子；刚下的那颗会多一个红圈。点到不合法的位置会抖动并给出一句原因（已有子 / 打劫禁着点 / 自杀）。
  • 右边有棋盘大小切换、提示、悔棋、再开一局、退出。围棋还多「弃权」和终局时的「结束并数子」。

每一局开始都会抛硬币：正面你执黑、先下；反面角色执黑、先下，你执白。黑子先下，之后双方轮流。棋局使用当前聊天已经配置好的 API，不需要再单独填一份。

AI 的棋力从哪来

落子由本地引擎计算：它先按棋型/气数/地域筛出几个像样的候选点，再把这些点交给模型，让模型挑一个并用角色的语气说话。模型只负责选点和演戏，不负责算棋。这样即使模型不擅长下棋，也不会走出「被叫吃还去别处铺子」这种臭棋；API 断了也能继续下。

棋盘大小可以在开局前选择，也可以在棋局右边随时切换（会重开一局）：五子棋 13 / 15 / 19 路，围棋 9 / 13 / 19 路。围棋坐标用围棋习惯的字母列号（A~T，跳过 I）+ 行号。

怎么下五子棋

五子棋默认使用 15×15 的棋盘,规则只看一件事:谁先把自己的五颗同色棋子连成一条直线(横、竖、斜均可),谁赢。棋盘可以在开局前选择 13 / 15 / 19 路,也可以在棋局右侧随时切换,切换会重开一局。

  1. 每局开局先抛硬币:正面你执黑先下,反面角色执黑先下、你执白。
  2. 黑白轮流,在任意空交叉点落子。已有棋子的位置不能再下,点下去会抖动并提示「这里已经有子了」。
  3. 中间不能断开,也不能借用对方的棋子。只要有一方连成五子,棋局立即结束。
  4. 棋盘下满仍无人连成五子,判为平局。

五子棋的常用判断

  • 活三 / 冲四:一条线上已有三颗且两端都是空位,叫「活三」,下一手就可能变成「活四」(两端都能成五)。一条线上已有四颗、只留一个空位,叫「冲四」,对方必须立刻堵住。
  • 优先级:先看自己能不能一手连成五子;再看对方是否有四颗要成五,必须先堵;然后再考虑自己进攻(连三、连四)。
  • 双活三 / 四三:一手同时形成两个活三,或者「冲四 + 活三」,对方通常只能堵一边,这是最常见的取胜方式。
不会下时可以这样做

先堵住对方已经连成三颗或四颗、且两端仍有空位的那一条。自己下的时候,尽量让一颗新棋子同时延长两个方向的线,既进攻又为以后留下「双三」的机会。不要只顾着连自己的棋,忘了对方下一步就能连成五子。

怎么下围棋

这里的围棋默认使用 9×9 的小棋盘,方便快速下完,也可以切换到 13 或 19 路。黑白轮流落子,目的不是连线,而是占住更多地盘,并吃掉对方没有活路的棋子。

基本规则

  1. 气:一颗棋子上、下、左、右紧挨着的空交叉点是它的「气」,斜角不算。相邻的同色棋子连成一块,整块共用这些气。
  2. 提子:把对方某一块棋的最后一口气堵住时,这一块会被整块提掉,对应位置变回空点。右侧会实时显示黑白各提了多少子。
  3. 禁止自杀:落子后自己这一块没有气、又没有同时提掉对方的棋,这一手不能下。点到这种位置会提示「自杀或循环局面,不能下这里」。
  4. 打劫:如果一方恰好提掉对方一颗子,而自己这颗子也只剩一口气,那么对方不能立即在被提的那个点回提(棋盘上会用禁着标记),必须先在别处应一手。点到禁着点时会提示「打劫禁着点,先在别处应一手」。
  5. 不能回到历史局面:任何会让棋盘回到之前某个局面的落子都不允许,这样能避免双方无限循环。

右侧操作栏

  • 提示:只在轮到你、且 AI 没有在思考时可用。引擎会在棋盘上标出它认为最好的一个点,并在聊天里说明,标记在你落子后自动消失。它只给建议,不会替你下。
  • 悔棋:退回到上一步之前的局面,用来改掉一手误着。悔棋时提子数会一并恢复。
  • 弃权:觉得没有更好的落点时,点「弃权」让手。双方连续弃权,就进入数子阶段。AI 也会在没有合适落点时弃权;如果 AI 连续两次弃权,同样直接进入数子阶段。
  • 再开一局 / 退出:「再开一局」会重新抛硬币;「退出」回到普通聊天界面。如果有未结束的棋局被保存,界面会出现「放弃存档」按钮,点了之后该局无法恢复。

数子与标记死子

  1. 双方连续弃权后,棋盘上还没有提干净的棋子(即死子)必须先清掉,才能正确数子。进入这一阶段时,提示会说明「双方连续弃权,进入数子阶段」。
  2. 自动猜测:系统会先按保守规则猜一遍死子:只剩一口气的棋块,以及周围空地很小、没有做眼余地的棋块。这只是猜测,请你务必自己复核,标错了会直接算错胜负。
  3. 手动标记:点击棋盘上的任意一块棋,可以在「死子」(棋子上出现金色叉)和「活子」之间切换,整块棋一起变化。
  4. 确认无误后点「结束并数子」。

怎么算胜负

使用数子法(中国规则):自己的活子数,加上被自己的棋完全包围的空点数。白棋自动加上贴目 5.5 目,用来抵消黑棋先下的优势;点数多的一方获胜,结果会显示在棋局状态里。

围棋坐标使用棋迷习惯的写法:列用字母 A–T(跳过 I),行用数字,例如「D4」。棋盘大小的切换见上文。

第一盘只要记住这些

先不要急着贴着对方下。把自己的棋子连在一起,留出足够的空地;看到对方一整块只剩一口气时,再把那口气堵住。地盘不需要围得严丝合缝,只要对方明显进不来,那片区域基本就算你的。数子前一定要把对方明显的死子标出来。

🕵️ 谁是卧底（实验室）

把线下那套桌游搬进来了：每人发一张词牌，大多数人拿到的是同一个词，有 1~2 个人拿到的是另一个近义词（卧底），但没人知道自己是哪一种。每轮各用一句话描述自己的词，一轮说完一起投票，票最多的出局、身份当场公开。

入口

「设置 → 实验室 → 谁是卧底 → 开一局」。至少 4 人（你 + 3 个角色）才能开；7 人以上自动两个卧底。它是独立界面，不进聊天记录，也不打扰你正在聊的对话。

怎么开局

  1. 选人当前在群聊里，可以直接点「用当前群聊的成员」；也可以自己从角色列表里挑。你自己永远算一个。
  2. 要不要明牌勾「明牌模式」时，发牌会告诉你自己是平民还是卧底；不勾就只给词，靠你自己判断。默认勾上，新手更好上手。
  3. 发牌右上角两张牌滑进来，先翻词牌显示你的词，再翻身份牌。之后随时点一下牌就能再看一眼。

一轮里发生什么

  • 描述：每轮随机顺序发言。AI 会按自己的角色口吻说一句话；轮到你时，底部的输入框出现，你说完点「说」。不能把词本身说出来——系统会拦，换个说法。说太直白等于把词送人，太含糊又会被投出去。
  • 不想说就跳过：轮到你时输入框旁边有「跳过」。跳过的这一轮记为「这轮没说话」——别人看得见，所以投票时会被怀疑，但不会被系统直接判死。
  • 投票：一轮说完，点一个你觉得最像卧底的人。AI 会看前面每一轮的发言和已经出局的人是什么身份再投，而且每票都带一句理由；结算页和「记录」面板都能看到谁投了谁、为什么。
  • 投票前还能追问：投票面板下面有个输入框，想问谁就问一句（最多两个人接话）。他们会替自己辩护、也可以反手怀疑别人——但不能说出自己的词，也不会承认身份。
  • 弃票：不想投就点「弃票」。全场都弃票时本轮没人出局。
  • 平票 → 加投：票最多的人并列时，先只在并列的那几个人之间再投一轮。加投还是平票，就按这一轮「谁说得最含糊」定一个人出局——不然票一散就会一轮轮空转，看着像卡住。
  • 出局：票最多的人出局，身份和词当场公开。
  • 观战：你先出局也不会结束，可以看 AI 们继续斗；只是不能再发言和投票。
  • 随时收场：右上角「结束」可以立刻结束这一局——不看胜负条件，直接把所有人的词和身份摊开。描述、投票、等 AI 说话的时候都能点，会先问一句再执行。

胜负

结果条件
平民赢卧底全部出局。
卧底赢活着的卧底人数 ≥ 活着的平民人数（也就是卧底再也投不出去了）。
拖太久打到第 12 轮还没分出胜负，算卧底赢。

AI 是真的在玩

每个 AI 只知道自己的那个词，不知道自己是平民还是卧底，也看不到别人的词——和真人局一模一样。所以卧底会真的按自己那个近义词去描述，可能露馅，也可能蒙混过关；平民则要想办法说得够具体、又不至于把词送给卧底。

它用的还是当前站点的模型，一次只说一句话、一句话的理由，token 消耗很小。投票时会把「谁已经出局、他是什么身份」一起给它——这是真人局里最有用的一条公开信息，之前没有喂进去，所以 AI 投起来像在瞎猜。

没配 API、或者模型一直连不上时也能开：AI 会换成按词的类别分组的本地兜底台词（吃喝、动物、数码、场所……各有各的一套），同一轮里不会两个人说出同一句。投票则退回到「谁的描述和场上其他人最不合群」，同样给理由——而且一个人最多吃一半的票，不会出现五个人排队投同一个、理由还一字不差的场面。不如真模型，但至少有据可依，不是掷骰子。

三个细节

退出不丢进度。关掉或刷新后，下次进来点「继续上一局」接着打；点「重新选人」才会覆盖。右上角那两张牌会跟着一起回来，不用重新发。

「结束」和「退出」不是一回事。「退出」只是先离开，进度留着；「结束」是把这一局收掉、当场摊牌，之后进大厅就看不到「继续上一局」了。

记录可翻。右上角「记录」里有每一轮所有人的发言，回头找谁前后矛盾很方便。

🐺 狼人杀（实验室）

把线下那套发言推理搬进来了：狼人夜里刀人、白天装好人，好人靠发言和投票把狼找出来。你会拿到一个真实身份——是狼就要参与刀人，是预言家就要验人，是女巫就要决定救不救。

入口

「设置 → 实验室 → 狼人杀 → 开一局」。至少 6 人（你 + 5 个角色），最多 12 人。身份按人数自动配好，独立界面，不进聊天记录。

五个身份

身份阵营能做什么
狼人狼夜里和同伴一起选一个人杀掉；白天要装成好人，可以撒谎、带节奏。知道彼此是谁。
预言家好每夜验一个人，立刻知道他是狼还是好人。信息最强，也最容易被狼盯上。
女巫好一瓶解药（知道当晚谁被刀，可以救）、一瓶毒药（可以毒死任何人），各一次，同一夜只能用一瓶。

一局怎么走

  1. 天黑狼人睁眼选目标。你是狼就由你来点；不是狼就看 AI 狼自己商量。
  2. 预言家验一个人，马上告诉你结果。只有你能看到。
  3. 女巫告诉你今晚谁被刀，再决定救、毒还是不用药。
  4. 天亮公布昨夜死者。如果是猎人被刀，会先让他开枪。
  5. 发言存活的人依次说一两句。轮到你时底部出现输入框，说完点「说」。
  6. 投票所有人一起投，票最多的被处决、身份当场公开。平票则无人出局，直接进下一夜。
  7. 再入夜活着的继续，直到分出胜负。

胜负

  • 好人赢：狼人全部出局。
  • 狼人赢：活着的狼数量 ≥ 活着的好人数量——也就是好人再也投不动了。

AI 是怎么玩的

每个 AI 只知道自己那份信息：狼认识狼同伴，预言家记得自己验过谁，村民什么都不知道。夜里刀谁、验谁、救不救、投谁，走的是本地规则（带随机），所以同一局能复现、也不会因为 API 挂了卡住。

只有白天的发言交给模型：提示词里会写清它是谁、什么身份、已知什么信息，让它按角色口吻说一两句。没配 API 时换成模板台词，游戏照样能打完，只是话变呆。

顶栏「结束」随时摊牌。不看胜负条件，直接公开所有人的身份；和「退出」不是一回事——退出只是先离开，进度留着。

你是狼的时候，同伴会给个「倾向」。那是 AI 狼的建议，你可以改，最终刀谁由你定。

🎓 学习辅导（实验室）

「学习辅导」在 设置 → 实验室 → 学习辅导（点「打开学习辅导」进入全屏界面），是一个拍题讲解的「辅导老师」：拍一张题目照片（或直接输入文字、Ctrl+V 粘贴截图），AI 会像老师一样给你讲题。所有讲解记录只存本机，可导出 JSON 备份。讲解使用当前已配置的 API；也可以在「设置 → AI 配置 → 专用模型 → 学习辅导」里单独指定一个支持视觉的模型（讲解需要识图）。

三种讲解模式

模式行为适合
引导式（默认）不给答案，先问你卡在哪一步，一步步引导你自己想出来平时做题、真的想学会
分步讲解把解法拆成 3~6 步逐步揭示，看懂一步再点「下一步」，讲完可一键总结知识点&套路看答案也不懂的题
完整讲解一次给全解题过程和答案赶时间、只想核对思路

讲题过程中可以直接在输入框继续追问（聊天式多轮对话）。讲完一道题后有四个操作：知识点&套路（总结考点）、举一反三（出同类型练习题，做完发回去会批改）、加入错题本、提新问题（清掉当前题目开始讲下一道；顶栏 ➕ 按钮也是同一个功能）。退出再进入时如果上次没讲完，会询问是否继续。

老师人设

「老师人设」可以换教学风格：默认辅导老师、温柔大姐姐、严格班主任、幽默段子手、猫娘老师，也可以完全自定义（名字 + 说话风格）。还可以用站内已有角色当老师（和论坛一样，内置角色和自定义角色都可以）：选中后老师会用那个角色的名字和性格讲课 —— 教学铁律（引导式不给答案等）永远优先于人设。另有「注入全局世界书」开关，给老师一套世界观背景。

错题本与学习档案

  • 错题本：做过的题收进来，可按科目/学段筛选，支持直接从错题本把题再调出来重讲。
  • 学习档案：讲过的题、知识点卡片会自动记一笔（本地完成，不额外消耗 API），老师「越用越懂你」。
  • 顶部可切换科目（可自定义增删）与学段/具体年级，界面顶部的科目、年级会随会话一起保存。

🎙️ 声音工坊：音色克隆与音高

入口：设置 → AI 配置 → 语音合成（TTS）。原来的「高级 TTS」和「实验室 → 声音工坊」已经合并成这一页：上半部分是接口与默认声音，下半部分是音色工坊与音色克隆。这一块负责「让 AI 用你想要的声音说话」，消息朗读、语音通话共用同一套参数。

音高（−12 ~ +12 半音）

音高滑杆与「语音合成 → 默认声音 → 音高」是同一个值，在哪边改另一边都会跟着变（面板里会实时同步）。但音色档自带的音高优先：给某个音色单独调过音高后，切到别的音色会回到那一档自己的设置。

端点类型音高怎么生效
MiniMax（/v1/t2a_v2）写进 voice_setting.pitch，是真正的变调，语速不受影响
支持 pitch 字段的中转 / 自建网关写进请求体，按原生处理
OpenAI 官方 /audio/speech 等不支持该字段的端点自动退成「播放速率折算」：按 2n/12 倍速播放，音高对了、语速会略微跟着变；试听时会明确提示走的哪条路
没配 TTS 端点（浏览器自带朗读）用 SpeechSynthesisUtterance.pitch，也是真变调

「不支持的端点」不会报错：TTS 会先用带音高的请求试一轮，失败后自动去掉音高字段重试，再退到播放速率折算，整条链路不会因此没声音。

克隆一个音色（以 MiniMax 为例）

MiniMax 的音色复刻分两步：上传素材拿 file_id → 用 file_id 创建音色。面板把这两步和「试听」「存成音色档」串在一起了，点一次按钮就走完。

  2. 选素材：点拖拽区或把文件拖进去，面板会显示大小与时长并做一次预校验（不满足就先提醒，省一次必然失败的请求）。
  3. 填 voice_id：可以自定义，例如 elysia_voice01。规则是字母开头、8~256 个字符、必须同时含字母和数字（elysia_voice 少一个数字就会被服务端拒绝，面板会提前标红提示）。
  4. 试听文本：例如 嗨~想我了吗？(chuckle)，克隆成功后会立刻用这个音色合成这句给你听。
  5. 模型：例如 speech-2.8-hd；旧账号需要的话再填 Group ID。
  6. 点「上传并克隆」：面板会逐行打印「上传 → 创建音色 → 保存音色档 → 合成试听」，哪一步失败就停在哪一步并给出可读原因。

克隆成功后会自动存成一个音色档（列表里带「克隆」标记）并启用。之后点「同步到默认声音」，把端点 / 模型 / voice_id 一并写进 TTS 配置，消息朗读和语音通话就都直接用这个克隆音色了。

Key 只保存在你自己的浏览器（localStorage）里，克隆请求由浏览器直接发往 MiniMax。如果浏览器报「连不上」，通常是对方没放开跨域（CORS）或网络不通，可以在端点里填入你自己的代理地址。

🧩 扩展模块（对标酒馆）

下面这组模块把「酒馆（SillyTavern）」上常见、而本站原来缺少或较弱的能力补齐了。它们都是可选的独立脚本：可以在「设置 → 导入导出 → 加载 JS 文件设置」里单独关闭；面板入口统一在设置 → 插件里；所有数据都只存在你的浏览器本机。

🔍 正则脚本（Regex）

用正则表达式在对话链路的六个位置自动「查找 → 替换」：用户输入 / 斜杠命令 / AI 输出 / 世界书 / 提示词组装 / 聊天显示。「AI 输出」会改写写入聊天记录的回复（持久生效）；「聊天显示」只改渲染、不动记录、不影响导出。替换串支持 $1 捕获组与 {{match}}、{{user}}、{{char}}、{{date}}、{{time}} 宏。

每条脚本可单独勾选参与哪些位置、调整执行顺序；面板带「试运行」与导入导出。典型用法：把 [emo:happy] 折叠成文字、统一 Markdown 风格、自动清理模型多余的格式标签。入口：设置 → 插件 → 正则脚本。

🌐 聊天翻译

每条消息气泡上有「译」按钮：点开看译文、再点收起；译文缓存在本机，重绘与刷新后自动恢复。引擎可选：AI 翻译（沿用当前站点或单独填接口）、Google、MyMemory、LibreTranslate、DeepL，共 11 种目标语言。设置里还能开启「自动翻译 AI 的新回复」与「翻译当前屏全部消息」。

重要边界：译文只用于显示，不写回聊天记录、不影响上下文与导出；这与「正则脚本 · AI 输出」位置有本质区别。入口：设置 → 插件 → 聊天翻译。

📋 提示词预设（Preset）

不改动任何角色卡，为每一轮请求叠加三层可编辑文本：主提示词（拼在系统提示词最前面）、辅助提示词（拼在末尾）、历史后指令（放在对话历史之后，越靠近模型最后读到的位置服从性越高，适合「只用中文回答」这类硬约束）。

模板支持 {{user}}、{{char}}、{{date}}、{{time}} 变量与条件块 {{#if 变量}}...{{else}}...{{/if}}；可建多套预设一键切换、复制与导入导出。入口：设置 → 插件 → 提示词预设。

🧪 消息脚本（JS）

正则不够用时，直接写一小段 JavaScript，在 用户输入 / 斜杠命令 / AI 输出 / 世界书 / 聊天显示 / 提示词组装 六个环节运行：return 新字符串 即生效（什么都不 return = 不修改）；提示词组装环节直接拿到完整的 messages 数组。可以做条件逻辑、快捷指令、查表替换等复杂自动化。

面板支持单条启用 / 排序 / 试运行 / 导入导出。总开关默认关闭；脚本以本页权限运行（等同 F12 控制台），请只粘贴你自己写的或可信来源的代码。入口：设置 → 插件 → 消息脚本。

🔖 聊天检查点与消息分叉

任意消息的操作栏里新增「检查点 / 分叉」入口：创建检查点把当前对话拍一张命名快照（不切换、不改动任何内容），之后随时整体恢复；从此消息分叉保留到那条消息为止、截断后面的内容，用来探索不同剧情走向。

「恢复」与「分叉」执行前都会自动再存一张「自动快照」，误操作可以反悔；最多保留 20 个检查点，支持导出 / 导入 JSON。入口：消息操作栏，或 设置 → 插件 → 聊天检查点。

🧠 聊天向量记忆（Vector Storage）

把聊天记录逐条向量化（存在本机 IndexedDB，按角色隔离，每个角色最多保留 800 条索引），每轮请求发出前用「你刚输入的话」做一次语义检索，把最相关的历史片段自动注入上下文 —— 即使那段对话早已滑出上下文窗口、也没被提炼成长期记忆条目，AI 依然能想起来。

嵌入配置留空会依次沿用「长期记忆 → 知识库 → 主配置」的地址与模型（还需要至少一处配置过嵌入模型，否则本模块静默不参与）。面板支持手动同步、清空当前角色索引与已索引条数统计。入口：设置 → 插件 → 聊天向量记忆。

🏦 数据银行（Data Bank）

集中管理供 AI 参考的文本资料（世界观设定、术语表、写作规范等），按三种作用域自动装载：全局（所有角色所有对话）/ 角色（指定角色的对话）/ 聊天（指定角色 × 指定对话，最精确）。

命中且启用的资料会在每轮请求发出前附加到系统提示词末尾（单轮注入上限 4000 字符，超出按顺序截断），不改聊天记录、不影响导出；支持整包导入导出。入口：设置 → 插件 → 数据银行。

🎨 AI 图像生成（多后端）

在聊天输入框直接输入 /img 画面描述（也支持 /画图）即可出图，生成结果自动以图片消息附加到当前聊天；也可以到面板里手动生成并预览。支持四种后端：Pollinations（免费公共接口，无需 Key）、OpenAI 兼容图像接口（DALL·E 3 / gpt-image-1 / 各类中转站）、Hugging Face（FLUX.1 等，需 Access Token）、Stable Diffusion WebUI（本机以 --api 启动）。

内置 45 种风格预设（动漫、水彩、写实、赛博朋克、吉卜力风……自动拼进提示词），可选尺寸与批量张数（1-4 张顺序生成），图片以 dataURL 保存、可随聊天记录一起导出。入口：设置 → 插件 → AI 图像生成。

🎭 VN Live2D 立绘

给视觉小说模式加上 Live2D：为角色配置 .model3.json 的 HTTPS 直链（Cubism 3/4，模型目录需允许跨域），进入 VN 后舞台上会显示可动立绘，自带呼吸、眨眼与待机动作；未配置或加载失败时自动回退静态立绘，不影响原有素材。

运行库（Cubism Core + pixi.js + pixi-live2d-display）只在真的配置了模型并进入 VN 时按需从 CDN 加载。入口：设置 → 插件 → VN Live2D 立绘。

😊 AI 生成人设（Persona 增强）

「用户人设」原本只能手写描述。现在世界书 Tab 的人设编辑区多了一个「AI 生成人设」按钮：输入几个关键词（身份 / 性格 / 背景 / 说话习惯），AI 会扩写成一段 150~350 字、可直接注入对话上下文的人设描述，并自动带上当前聊天角色的名字；填入描述框确认后点「保存人设」即生效。会消耗你所配置 API 的额度。

🌐 AI 英文模式

一个总开关，让 AI 在勾选的场景里只说英文，界面文字不受影响。生效范围可逐个勾选：正常聊天（含群聊、上线问候、主动关怀）、AI 直播间（台词 / 弹幕）、论坛（发帖 / 评论 / 私信）、学习辅导（讲解 / 追问 / 辅导通话）、语音 / 视频通话、小游戏（棋局闲聊、森林冰火人）。规则以「最高优先级」追加在系统提示词末尾，覆盖角色卡里要求中文的旧指令；表情占位符、分步讲解的【第N步】等格式标记保持原样，相关功能不受影响。

  • 让活跃角色逛逛论坛：立即让一个（按活跃度加权随机选出的）角色在随机分区发一帖，并可能触发其他角色的点赞与评论。

❓ 常见问题 FAQ

Q1：填写完 API Key 但还是提示「请先配置 API」？

A：检查是否点过 「保存设置」（不是「测试连接」）。保存后会自动关闭弹窗。如仍报错，刷新页面重试。

Q2：AI 回复到一半就断了？

A：通常是触发了 maxTokens 上限。在设置里调大「单条回复上限」即可。

Q3：AI 经常「失忆」忘记前文？

A：调大「最大上下文轮数」。但注意：上下文越大，每次消耗的 Token 越多、费用越高。

Q4：「测试连接」成功，但实际聊天报错？

A：可能是 Key 余额不足、模型名称写错、或平台风控拦截。检查 Key 对应平台的「用量」和「模型名是否含特殊前缀」。

Q5：如何切换不同模型给不同角色？

A：当前版本所有角色共享同一套 API 配置。如需为不同角色指定不同模型，可在使用中临时切换全局设置。

Q6：可以把聊天记录分享给朋友看吗？

A：可以。点击聊天右上角 → 切换到「导入导出」标签 → 导出单角色聊天记录为 JSON 或图片长截图。

Q7：支持语音输入 / 语音回复吗？

A：支持。语音输入默认用浏览器原生识别，部分浏览器（如夸克）原生识别不可用；可在「设置 → AI 配置 → 语音转文字（STT）」配置 OpenAI 兼容的 /v1/audio/transcriptions 接口（如 whisper-1），配置后语音按钮会改为「录音 → 上传转文字」，保存后立即生效。AI 语音播报（TTS）在「AI 配置 → 语音合成」里配置。

Q8：能换主题色吗？

A：顶部 按钮可切换深色 / 浅色主题。主题色在 CSS 变量中定义，高级用户可自行修改 style.css。

Q9：AI 会把我的对话拿去训练吗？

A：取决于你使用的 API 平台。多数付费 API 平台明确表示不会用你的 API 调用数据训练模型（详见各平台隐私政策）。本应用本身是纯前端应用，不可能收集你的数据。

Q10：访问 https://mysw-yg.pages.dev 看不到侧边栏角色？

A：首次访问时浏览器会预加载约 900KB 的角色数据，请稍等几秒。如仍为空，按 Ctrl+F5 强制刷新。

Q19：测试连接报「模型不存在 / 404 / invalid model」，是不是 Key 坏了？

A：多半不是。这是模型名过期——厂商下线旧模型、换上新模型，旧名字就不再受理。典型例子：DeepSeek 的 deepseek-v4-flash 和 deepseek-v4-pro 已在 2026 年 9 月下线，现在要填 deepseek-flash。修法只有一步：点「获取模型」，从平台真实返回的列表里选一个，别照旧教程抄名字。详见 常见 API 平台推荐 开头那条提示。

如果「获取模型」也报错，才是 Key / 地址 / 网络的问题。

Q11：一打开就弹出「欢迎来到 My SW」的弹窗，可以关掉吗？

A：那是首次访问引导，只会在完全没有任何使用痕迹时出现（没配过 API、没有自定义角色、也没有聊天记录）。点「查看使用文档」或「先自己逛逛」都会记住，之后不再打扰。它只提示一件事：可以去 https://mysw-yg.pages.dev/docs 查阅使用文档。

Q12：开了？？？模式还是觉得卡怎么办？

A：按顺序试：① 在「设置 → 界面外观 → 动效等级」里把等级降到「轻量」，只保留弹窗展开与按压反馈；② 关掉「毛玻璃效果」（大面积 backdrop-filter 是低端设备掉帧的主要原因）；③ 仍然卡就切换到「兼容模式」，它会关闭全部动画与过渡。注意旧的？？？模式曾是常驻循环动画（渐变位移 + hue-rotate + 无限旋转），现已完全重写为「播一次就停」的动效，正常情况下不会再持续占用 GPU。

Q13：想固定角色列表的顺序，不想被「最近聊过」打乱？

A：到「设置 → 界面外观」，关掉「最近聊过的角色排在前面」，列表就只按你手动拖出来的顺序排列。这个功能本身也不会影响置顶角色 —— 置顶永远优先。

Q14：好感度会不会太快刷满？

A：「设置 → 实验室 → 好感度」里所有参数都能改。嫌快就把「档位衰减系数」调小（例如 0.7）、把「每人每日上限」调低，或把某个角色的倍率单独调到 0.5。想彻底不看衰减，把「每天自然衰减」设为 0 即可。

Q15：我自己写的插件为什么不生效？

A：按这个顺序检查：① 插件卡片上的「启用」是否勾上；② 卡片上有没有黄色提示条（说明权限没给全，需要先在「插件权限」打开总开关）；③ 控制台有没有 [插件名] xxx 失败 的警告；④ id 是否与已有插件重复（重复会覆盖）。详见 插件编写指南。

Q16：论坛里的数据能备份吗？换设备怎么带过去？

A：可以。右侧栏有「导出论坛数据 / 导入论坛数据」，导出会得到一个包含帖子、评论、私信、关注、收藏与分区设置的 JSON 文件。在另一台设备上导入时可选「合并」（按 id 去重后追加）或「覆盖」。合并导入会保留互动数更多的版本，不会把点赞清零。

Q18：AI 老是叫错我的名字，或者把我当成两个人？

A：两种原因。① 叫错名字：默认会把你的账号昵称写进提示词，昵称改过之后旧对话里它还记着旧的 —— 改完昵称后开一条新对话即可，或者干脆到「设置 → 聊天设置 → 上下文与记忆」关掉「把『我的昵称』发给 AI」。② 当成两个人：多半是语C 时昵称和你要演的角色不是同一个，提示词里同时出现「用户叫 A」和「用户在演 B」。详见 语C 章节。

Q17：我在「设置 → 插件」里看到一批新的扩展（正则脚本 / 聊天翻译 / 提示词预设 / 消息脚本 / 聊天检查点 / 向量记忆 / 数据银行 / 图像生成 / Live2D / 人设生成），需要另外安装吗？

A：不用，它们随主站一起加载、默认就开着。不想用时有两种关法：① 在对应面板里关掉功能开关（数据保留）；② 到「设置 → 导入导出 → 加载 JS 文件设置」里把整个脚本关掉（入口消失、功能停用，已保存的数据不会被删除）。详见 扩展模块 章节。

Q20：点「保存设置」之后，提示「设置没能保存 / 本地存储已满」？

A：浏览器给每个站点划的 localStorage 只有几 MB，而聊天记录是其中最大的一块。存满之后，连几 KB 的 API Key 都写不进去 —— 表现就是「填好、点保存、关掉再打开又空了」。 现在的版本会在保存失败时明确告诉你哪几项没存上，并给一个「去清理」入口：到存储面板勾「只选可再生项」（缓存、缩略图这类），清完再点一次保存即可，聊天记录不会被删。 另外，聊天记录超过约 120 万字符后，localStorage 里只保留最近十几条的镜像，完整记录依然在 IndexedDB 中，导出和继续聊天都不受影响。
